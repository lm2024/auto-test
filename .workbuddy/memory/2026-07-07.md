## 启动前后端服务的坑（当晚实测）

- **后端启动必须用「受工具托管的后台任务」**：之前用 `nohup ... &` + 后台任务包裹，任务 shell 退出时会把子进程（JVM）一起回收，导致后端卡死/消失（日志停在 banner）。正确做法：`run_in_background=true` 直接跑 `mvn spring-boot:run`，不加 `nohup`/`&`。
- 后端命令：`export JAVA_HOME=<corretto-1.8.0_462> && export SERVER__PORT=8080 && mvn spring-boot:run`（JDK 8 必需；`SERVER__PORT` 防环境变量劫持端口）。
- **真实登录接口是 `/api/user/login`**（UserController），不是 `/api/auth/token`。前端 `Login.vue` 调的就是它。AuthController 的 `/api/auth/token` 是另一回事。
- 环境有 `HTTP_PROXY=127.0.0.1:51870`，导致 `curl localhost` 走代理返回 502/000；本机探测需 `curl --noproxy '*'` 或 `nc`。
- **前端 Vite 默认绑定 IPv6 `::1`**（非 127.0.0.1），探测/访问要用 `http://localhost:3001/` 而非 `127.0.0.1:3001`。
- 数据库容器 `auto-test-mysql`（MySQL 8.0，端口 3306）由 Docker 常驻，无需每次重启。

## 用户实际访问后发现的 2 个真实 Bug（已修复）

用户打开页面后发现：① 左侧菜单「用户管理/定时任务」不见了；② 执行详情页 `EXEC_268151FE7C` 平铺/分组视图全空白。排查与修复：

1. **【严重】节点日志永不落库 → 执行详情整页空白**。
   - 现象：`/api/execute/nodeLogs` 返回 `"data":[]`，但 `/api/execute/status` 显示 `nodeCount:1`。全表 `test_node_execute_log` 行数 = 0。
   - 根因：`ExecuteServiceImpl` 的 `batchInsert` 被 `try/catch` 静默吞异常；真正异常是 `Unknown column 'biz_oper_trace_id' in 'field list'`。实体类 + Mapper 引用了 `biz_oper_trace_id` 和 `sort_no` 两列，但**表的 DDL（含 `docker/init.sql`）缺这两列**，且 `SELECT *` 不报错掩盖了问题。
   - 修复：运行中库 `ALTER TABLE test_node_execute_log ADD COLUMN biz_oper_trace_id varchar(64), ADD COLUMN sort_no int;`；并补 `docker/init.sql` 防止重建库复发。无需改代码（代码本就对）。
2. **【功能】ADMIN 菜单不显示**。
   - 根因：`App.vue` 是根布局只挂载一次，`const user = ref(getUser())` 在启动未登录时求值成 `null`；登录后 `localStorage` 虽写入带 `role:ADMIN` 的 user，但 `user` ref 不重算 → `v-if="user && user.role==='ADMIN'"` 永假 → 用户管理/定时任务隐藏，用户下拉也隐藏。
   - 修复：`App.vue` 加 `watch(() => route.fullPath, () => user.value = getUser())`。
   - 验证：用全新上下文 Playwright 登录 admin，修复前菜单只有 6 项、用户管理可见数=0；修复后 8 项齐全、用户管理可见数=1；详情页平铺/分组各渲染 2 张卡片、控制台零报错。
