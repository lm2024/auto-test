# 纯内网 / 无外网 / 无 Docker 部署 —— 需要改动的地方清单

> 适用场景：把**前端 + 后端 + 浏览器插件**部署在纯局域网、无外网、无 Docker 的环境中（后端 jar 直跑 + 前端静态托管 + 插件手动加载）。
> 本文档只汇总「要改 / 要配」的地方，不重复讲解架构。

---

## 0. 一句话结论

本项目**写死的 IP 很少**。前端 API 和 WebSocket 都是相对路径，**前端代码本身几乎不用改 IP**。真正要动的是：

1. 后端 `application.yml` 里的数据库 / AI / 安全密钥；
2. 浏览器插件里的「后端 / 前端地址」（运行时填 or 写死兜底）；
3. 所有引用 **Google Fonts CDN** 的地方（不删会白屏 / 卡死）；
4. 生产环境前端静态托管需要把 `/api`、`/ws` 指到后端（nginx 反代 or 改 baseURL）。

---

## 1. 后端 `backend/src/main/resources/application.yml`

（已为你加好中文备注，配置值未变。）

### 1.1 必改（不改成内网地址就跑不通）

| 配置项 | 当前默认 | 内网应改为 | 说明 |
|--------|----------|-----------|------|
| `spring.datasource.url` | `jdbc:mysql://localhost:3306/auto_test...` | `jdbc:mysql://<内网MySQL_IP>:3306/auto_test...` | 数据库不在本机必改 |
| `spring.datasource.username` | `root` | 内网 MySQL 账号 | |
| `spring.datasource.password` | `AutoTest2026Kp9&Xz*` | 内网 MySQL 密码 | 明文，建议改 |
| `ai.base-url` | `http://localhost:11434/v1` | 内网可达的 LLM 地址 `http://<AI机IP>:11434/v1` | 默认指向本机 Ollama |
| `ai.api-key` | `sk-placeholder` | 内网模型 key | |
| `ai.model` | `qwen-max` | 内网实际模型名，如 `qwen2.5:7b` | ⚠️ `qwen-max` 是通义云模型名，纯内网无该模型必须改 |

> 备注：即使内网**完全没有 LLM 服务**，AI 生成测试数据 / 失败分析会失败，但**核心执行链路不受影响**，可先留默认部署。

### 1.2 建议改（不改能跑，但等于裸奔）

| 配置项 | 说明 |
|--------|------|
| `account.aes-key` | 测试账号密码 AES 密钥，当前是公开默认值 `autotest_key_16!`（必须 16 字节 ASCII）。内网不可信 / 存了真实凭证 → 必须改 |
| `jwt.secret` | 登录 token 签发密钥，当前公开默认值。不可信环境 → 建议改 |
| `jwt.expiration` | token 有效期（毫秒），`86400000` = 24h，按需调长 / 调短 |

> **改了 `aes-key` / `jwt.secret` 后的副作用**：之前已加密存的测试账号密码会解不开（需重新录入）；已登录用户的 token 全部失效（重登即可）。**建议第一次部署、尚未录数据前就改。**

### 1.3 可不改 / 可删

- `server.port: 9093`：可保持，或改成内网统一端口。
- `sso.*` 整段：已加备注。`enabled: false` 时下列子项全部不生效，整段可删，后端照样启动。

### 1.4 推荐：用命令行参数覆盖，配置不落明文

```bash
java -jar backend.jar \
  --spring.datasource.url=jdbc:mysql://<MySQL_IP>:3306/auto_test \
  --spring.datasource.password=你的库密码 \
  --ai.base-url=http://<AI_IP>:11434/v1 \
  --ai.model=qwen2.5:7b \
  --account.aes-key=你的16字节密钥 \
  --jwt.secret=你的随机串
```

## 2. 前端 `frontend/`

### 2.1 【必改】Google Fonts CDN（共 4 处源码，不删会断网卡白屏）

| 文件 | 行 | 内容 |
|------|----|------|
| `frontend/index.html` | 7–9 | 3 个 `<link>` 引 `fonts.googleapis.com` / `fonts.gstatic.com`（Inter 字体）|
| `frontend/src/App.vue` | 195 | `@import url('https://fonts.googleapis.com/...Inter')` |
| `frontend/src/views/ExecuteDetail.vue` | 257 | `@import url('https://fonts.googleapis.com/...Plus Jakarta Sans')` |
| `frontend/src/views/ChainEdit.vue` | 1306 | `@import url('https://fonts.googleapis.com/...Plus Jakarta Sans')` |

**改法**：删掉这些 `<link>` 和 `@import`，把用到这些字体的 CSS `font-family` 改成系统字体栈：

```css
font-family: system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif;
```

> 注意：`frontend/dist/`（构建产物）里也含这些引用，改完源码后**重新 `npm run build`** 即可覆盖。

### 2.2 API / WebSocket 地址（基本不用改）

- `frontend/src/api/index.js`：`baseURL: '/api'`（相对路径）
- `frontend/src/views/ExecuteDetail.vue`：`ws://${location.host}/ws/...`（相对路径）

两者都走「同源」，所以前端和后端必须**同 host:port**，或靠反代把它们合到同一入口（见 2.3）。**不用改代码里的 IP。**

### 2.3 生产静态托管如何指向后端（二选一）

> `vite.config.js` 里的 `proxy` **只在 `npm run dev` 生效**，生产 `npm run build` 后无效。

- **方案 A（推荐）nginx 统一入口**：nginx 监听 80 / 9094，把 `/api`、`/ws` 反代到后端 `9093`，前端 `dist/` 用相对路径零改动。见第 4 节。
- **方案 B 注入绝对地址**：打包时设 `VITE_API_BASE=http://<后端IP>:9093`，并把前端 `baseURL` 由 `/api` 改为 `${import.meta.env.VITE_API_BASE}/api`。需改 `src/api/index.js`。

## 3. 浏览器插件 `plugin-test/`

插件「推送服务端」就是调你们那个后端（同一套 `/api/plugin/...`），**没有第二个独立服务**。地址通过「设置」填，或写死兜底值。

### 3.1 运行时设置（设计本意，无需改代码）

加载解包扩展后，打开侧边栏 → 设置，填两项（存 `chrome.storage`）：

- 后端 API 地址 `cfgUrl` → `platformUrl` → `http://<后端内网IP>:9093`
- 前端页面地址 `cfgFrontendUrl` → `frontendUrl` → `http://<前端内网IP>:9094`

⚠️ **不填会静默回退到 `http://localhost:9093`**，以为后端在本机，推不出去。**必须填。**

### 3.2 【可选】把兜底默认值写死（适合团队，免每人手填）

`plugin-test/sidepanel.js` 里共 8 处兜底地址（改了即使不进设置也能连）：

- `platformUrl` 兜底 5 处：`http://localhost:9093`（行 411 / 480 / 562 / 691 / 1080）
- `frontendUrl` 兜底 3 处：`http://localhost:9094`（行 155 / 1107 / 1161）

把 `localhost` 换成你们内网 IP 即可。`sidepanel.html` 输入框 `placeholder`（行 588 / 589）也一并改掉提示文本。

### 3.3 【必改】插件 Google Fonts CDN

`plugin-test/sidepanel.html` 行 7–9：3 个 `<link>` 引 `fonts.googleapis.com` / `fonts.gstatic.com`（Noto Sans SC）。纯内网会卡。删掉即可（用系统字体）。

## 4. nginx 反代配置示例（内网生产，方案 A）

```nginx
server {
    listen 9094;
    server_name _;

    # 前端静态文件
    root /opt/autotest/frontend/dist;
    index index.html;
    try_files $uri $uri/ /index.html;

    # 后端 API
    location /api/ {
        proxy_pass http://<后端IP>:9093/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # WebSocket
    location /ws/ {
        proxy_pass http://<后端IP>:9093/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```

## 5. 数据库（无 Docker）

1. 服务器装 **MySQL 8.0**（字符集 utf8mb4）；
2. 导入初始化脚本（纯 SQL，无 Docker 也能用）：

   ```bash
   # ① 首次部署：外层完整建库脚本（自带 CREATE DATABASE + USE，可直接执行，无需先建库）
   mysql -uroot -p < docker/init.sql

   # ② 如需"回放 / 版本快照"功能，再跑内层增量升级脚本（它不含建库语句，需指定库名）
   mysql -uroot -p auto_test < auto-test/backend/docker/init.sql
   ```

   > ⚠️ **两份 init.sql 不一样，不能混用**：
   > - `docker/init.sql`（外层）= **完整建库脚本**（建库 + 建表 + 默认数据），首次部署用这一份；
   > - `auto-test/backend/docker/init.sql`（内层）= **增量升级脚本**（给已有库加回放 / 版本快照表），**必须先跑外层、再跑它**，不能直接单独执行（否则 `ALTER TABLE test_chain` 报"表不存在"）。
   > - 外层脚本含 `DROP TABLE IF EXISTS ... CREATE TABLE`，会清空同名表已有数据，仅首次部署或可接受清空时执行。
   >
   > 默认管理员账号 `admin / Admin@123` 已由脚本预置（BCrypt 哈希，存于 `sys_user` 表），执行外层脚本后即可用该账号登录。`account.aes-key`（AES）只用于 `test_account` 测试账号表，与平台 admin 登录无关。

## 6. 完整部署步骤（最原始版）

```
1. 装 MySQL 8.0 → 建库 auto_test → 导入 init.sql
2. 改 backend/src/main/resources/application.yml：
     - datasource.* 指向内网 MySQL
     - ai.* 指向内网 LLM（无 AI 服务可留默认，核心执行链路不受影响）
     - 建议改 account.aes-key / jwt.secret
3. 打包后端：mvn clean package → 得到 backend.jar
4. 改前端 4 处 Google Fonts（删 CDN）→ npm install → npm run build → 得 dist/
5. 部署前端 dist/ 到 nginx（或任意静态服务器），nginx 反代 /api、/ws 到后端 9093
6. Chrome 加载解包的 plugin-test → 设置里填后端/前端内网地址；删 sidepanel.html 的字体 CDN
7. 启动：java -jar backend.jar；启动 nginx
```

## 7. 「不改到底行不行」速查表

| 项 | 不改行不行 | 前提 |
|----|-----------|------|
| 数据库 / AI 地址 | ❌ 不行 | 必须指向真实可达的内网服务 |
| Google Fonts（前端 + 插件）| ❌ 不行 | 纯内网无外网，会被卡死 / 白屏 |
| 插件地址 | ❌ 不行（必须填）| 不填回退 localhost，推不出去 |
| `account.aes-key` / `jwt.secret` | ✅ 可暂不改 | 内网可信 + 不存真实凭证 |
| `sso.*` 整段 | ✅ 可删可留 | 默认关闭，不生效 |
