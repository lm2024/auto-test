# 前端内网部署改动清单

> 针对 `auto-test/frontend/` 在**纯内网 / 无外网 / 无 Docker** 环境下的所有改动点。
> 后端、插件、数据库的改动见《内网部署改动清单.md》。

---

## 0. 结论速览

前端**几乎没有写死的 IP**——API 和 WebSocket 都走相对路径。纯内网部署前端真正要处理的是：

1. **【必改】** 删掉 4 处 Google Fonts CDN 引用（否则白屏 / 卡死）；
2. **【理解】** API / WS 走同源相对路径，生产环境需靠反代或改 baseURL；
3. **【必做】** `npm run build` 产出 `dist/`，用静态服务器 + nginx 反代托管。

---

## 1. 必改：Google Fonts CDN（共 4 处源码）

纯内网无外网，这些外链会一直请求超时，导致页面卡白屏。**这是前端唯一会"断网即崩"的硬伤。**

| 文件 | 行 | 引用内容 |
|------|----|---------|
| `frontend/index.html` | 7–9 | 3 个 `<link>`：`fonts.googleapis.com` / `fonts.gstatic.com`（Inter 字体）|
| `frontend/src/App.vue` | 195 | `@import url('https://fonts.googleapis.com/...Inter')` |
| `frontend/src/views/ExecuteDetail.vue` | 257 | `@import url('https://fonts.googleapis.com/...Plus Jakarta Sans')` |
| `frontend/src/views/ChainEdit.vue` | 1306 | `@import url('https://fonts.googleapis.com/...Plus Jakarta Sans')` |

### 改法

**方式一（最小改动，推荐）**：直接删除上述 `<link>` 和 `@import` 行。
删除后，原本 `font-family: 'Inter', sans-serif` 会自动回退到系统 `sans-serif`，页面正常显示，只是字体变为系统默认（完全可接受）。

**方式二（效果更可控）**：删除 CDN 引用后，在全局样式把字体栈统一为系统字体：

```css
:root {
  --font-sans: system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif;
}
body, .app, .el-*, .node-card { font-family: var(--font-sans); }
```

> ⚠️ `frontend/dist/` 是构建产物，里面也含这些 CDN 引用。改完源码后**必须重新 `npm run build`** 才能生效。

---

## 2. 不用改但要理解：API / WebSocket 地址

| 位置 | 当前写法 | 说明 |
|------|---------|------|
| `frontend/src/api/index.js` | `baseURL: '/api'` | 相对路径，**不写死 IP** |
| `frontend/src/views/ExecuteDetail.vue` | `ws://${location.host}/ws/...` | 相对 host，**不写死 IP** |

因为是相对路径，前端页面必须和后端**同源（同 host:port）**，或靠反代把它们合到同一入口。**这些是相对路径，不用改代码里的 IP。**

---

## 3. 生产静态托管如何指向后端（二选一）

> `frontend/vite.config.js` 里的 `proxy`（`/api` → `localhost:9093`、`/ws` → `ws://localhost:9093`）**只在 `npm run dev` 生效**，生产 `npm run build` 后无效。

### 方案 A（推荐）：nginx 统一入口，前端零改动

nginx 监听 9094，把 `/api`、`/ws` 反代到后端 9093，前端 `dist/` 直接托管。前端代码不用动。nginx 配置示例见《内网部署改动清单.md》第 4 节。

### 方案 B：注入绝对地址（需改一处代码）

打包时设 `VITE_API_BASE=http://<后端IP>:9093`，并把 `src/api/index.js` 的 baseURL 改为：

```js
baseURL: import.meta.env.VITE_API_BASE || '/api'
```

WebSocket 地址同理改为读取环境变量。适合前端和后端长期跨域、不用 nginx 的场景。

---

## 4. 前端构建与部署步骤

```bash
cd auto-test/frontend
npm install          # 依赖已全部本地化在 node_modules，无需外网
# 先按第 1 节删掉 Google Fonts，再 build
npm run build        # 产出 dist/
# 把 dist/ 丢到 nginx 的 root 目录，或由任意静态服务器托管
```

要点：
- 必须 `npm install` 装依赖（依赖已本地化，无需外网下载）；
- `npm run build` 生成的 `dist/` 是纯静态文件，拷贝到内网任意机器即可；
- 生产环境靠 nginx 反代 `/api`、`/ws`（见方案 A）。

## 5. 可优化（非必改）：LogicFlow 死依赖

`package.json` 声明了 `@logicflow/core`、`@logicflow/extension`，但**源码未引用**——流程编排是手搓列表式（`ChainEdit.vue` 用 div + 原生拖拽）。纯内网无影响，但可删除以减小 `node_modules` / 打包体积。
