# 全局总纲（最高规则）
2. 所有业务文档平铺根目录，命名格式：需求号-主任务号-原子任务号-名称.md，编号为两位数字。
4. 任务按「整体需求→主任务→原子任务」拆分，单会话仅执行单个原子任务。
5. 代码修改模块/文件相互隔离，禁止范围重叠与冲突。
6. 有依赖任务按先后顺序执行，无依赖任务可并行。
7. 任务完成建议关闭当前会话，新建会话执行下一任务。
8. 所有细分规则请查阅规则索引，按需读取。
9. 类，文档必须遵循限制行数400左右，不能超过500行，如果超过就拆分多文档
10. 如果类超过行数限制就说明设计不合理，需要对上下文关联的类方法进行重构。
11. 行数超限的核心思想就是拆分，编写多个文档或多个类进行合理拆分
12. 文档编写格式要简单，但是内容要丰满
