# 一、TraceId 生成位置标准答案
**必须在浏览器插件侧生成操作级 TraceId（命名：bizOperTraceId），服务端只做透传、不生成**
1. 浏览器插件点【开始录制】→ 立刻生成唯一 bizOperTraceId，存入插件内存；
2. 拦截所有 fetch/xhr 请求，给请求头塞入 `X-Biz-Oper-Trace: ${bizOperTraceId}`；
3. 后端网关/Filter 读取该 Header，塞入 MDC，再透传给 Dubbo/Feign/MyBatis 全链路；
4. 服务端原有链路追踪 traceId（skywalking/jaeger）保留，只做监控；**区分开全局调用链ID 和 业务操作录制ID**，不要混用。

核心逻辑：一次人工操作的边界由浏览器人的操作定义，浏览器才知道“用户什么时候开始操作、什么时候结束”，服务端无法感知用户点击、下拉等交互行为，所以不能由服务端生成这条业务操作分组ID。

# 二、核心问题：10条过滤后的接口里，只3条属于本次操作，其余7条无关，精准分组方案（黑白名单已做，不再重复）
## 方案1：时间滑动窗口 + 操作触发锁（最核心，解决混杂请求）
### 1）触发时机
只有用户主动交互才激活采集窗口：click、select下拉change、输入回车、弹窗确认。
触发后开启**滑动窗口（可配置2~4s）**，窗口生命周期规则：
- 窗口内所有带 bizOperTraceId + 命中白名单的接口 → 归属本次操作；
- 窗口内新产生业务接口，自动延长窗口（最长上限5s，防止无限拉长）；
- 窗口超时无新业务请求 → 关闭本条链路，封存。

### 2）无关请求自动剥离逻辑
10条白名单接口，时序分布示例：
1. 录制启动前置加载（窗口未激活，丢弃）
2. 心跳定时接口（窗口未激活，丢弃）
3. 用户点击新增按钮 → 激活窗口，bizOperTraceId注入
4. 新增保存接口（窗口内 → 保留）
5. 页面字典下拉加载（窗口内 → 保留）
6. 查询列表接口（窗口内 → 保留）
7. 后台轮询刷新（窗口未激活，丢弃）
8. 埋点上报（黑白名单已过滤）
9. 全局token刷新（窗口未激活，丢弃）
10. 页面静态资源（黑白名单过滤）

最终仅4/5/6三条被分组到同一个 bizOperTraceId 链路，其余直接剔除。

### 3）多条操作自动切分
- 第一次点击：TraceA，窗口0~4s
- 间隔6s（超过窗口阈值）再次点击查询：新建 TraceB，独立链路
两段操作彻底分开，不会混在一条用例。

## 方案2：交互事件上下文绑定兜底（窗口失效场景补充）
每条被采集的请求额外存储元数据：
- triggerEvent：触发事件类型（click/select/input）
- targetDom：操作DOM标识（按钮id、下拉选择器、弹窗标识）
- pageUrl：当前页面地址

校验规则：同一 bizOperTraceId 下，所有保留接口必须**页面URL一致 + 落在操作时间窗口内**。
如果出现同TraceId但跨页面、远超窗口时长的请求，后置清洗脚本自动剔除。

## 方案3：插件实时标记剔除（人工辅助精准过滤，解决边缘脏数据）
录制面板展示所有窗口内捕获的接口，分两类：
1. 自动推荐保留（窗口内、操作直接关联）；
2. 可疑无关接口（定时轮询、后台异步刷新、全局基础数据加载）标灰。
用户录制时可一键取消勾选，后台给该请求打上 `ignore: true` 标记，持久化到用例，回放时直接跳过。

# 三、前后端链路关联完整流程（打通前端操作+后端上下游调用）
1. 浏览器插件开启录制，生成 bizOperTraceId；
2. 用户点击按钮，激活时间窗口，所有业务请求携带该ID；
3. 后端拦截器提取Header，MDC透传至HTTP、Dubbo、SQL、Redis；
4. 所有后端底层调用（入库、查询RPC）均绑定同一个 bizOperTraceId；
5. 存储层聚合逻辑：以 bizOperTraceId 作为分组主键，按时间正序拼接：
   前端操作事件 → 前端接口请求 → 后端HTTP入口 → Dubbo调用 → SQL语句
6. 回放时，按该分组完整复现整条业务链路，自动丢弃所有不在分组内的请求。

# 四、区分两个Trace，避免混淆（极易踩坑）
1. X-TraceId（SkyWalking/链路监控）：一次完整请求的分布式追踪ID，一个接口一个；
2. X-Biz-Oper-Trace（自研录制分组ID）：**一次用户操作的全链路分组ID**，一次点击/下拉对应一条业务用例，包含多个X-TraceId。

# 五、极简落地规则总结
1. 操作分组ID只在浏览器插件生成，服务端仅透传；
2. 靠「用户交互触发+限时滑动窗口」划定链路边界，自动分离无关白名单接口；
3. 同分组标准：同一bizOperTraceId + 落在激活窗口内 + 同页面；
4. 可疑脏接口支持录制时手动剔除，永久生效；
5. 存储以bizOperTraceId聚合前后端全链路，形成纯净可回放单业务用例。
