| 问题 | 痛点 | 解决策略 |
|------|------|---------|
| **登录兼容** | 不同系统登录方式各异（传统密码、验证码、OAuth2、SAML、CAS、Cookie 会话等），没有登录就不能测试 | 双轨制：①增强 AuthService 支持多种认证协议 ②引入 Playwright 浏览器引擎处理复杂登录 |

## 二、核心概念：链路模板 + 数据池

### 2.1 为什么需要"模板"

**用户痛点：** 同一个业务流程（如"创建订单"），每次执行时订单号、商品 ID、金额等参数都不同。如果每次都重新录制，效率极低。

**解决方案：链路即模板。**

```
录制一次 → 链路（Chain）
              ↓
    用户将动态值替换为 ${变量名}
              ↓
    这条链路就是"模板"
              ↓
    绑定数据池 → 每轮执行时从数据池取不同参数注入
```

**这不需要新建"模板"实体。** 现有的 Chain 本身就是模板——它存储的是流程骨架（URL、方法、headers 结构），变量占位符 `${varName}` 是参数化接口。数据池提供参数值。执行引擎在运行时将两者结合。

**举例：**
```
录制的链路（模板）：
  Node1: POST /api/order/create
         Body: {"productId": "${productId}", "quantity": ${quantity}, "price": ${price}}
  
  Node2: POST /api/order/pay
         Body: {"orderId": "${orderId}"}  ← orderId 从 Node1 响应提取

数据池（3 轮数据）：
  Row 0: {"productId": "P001", "quantity": 1, "price": 99.00}
  Row 1: {"productId": "P002", "quantity": 3, "price": 199.00}
  Row 2: {"productId": "P003", "quantity": 2, "price": 299.00}

执行结果：
  第 1 轮：使用 Row 0 参数 → 订单 001
  第 2 轮：使用 Row 1 参数 → 订单 002
  第 3 轮：使用 Row 2 参数 → 订单 003
```

### 2.2 变量优先级

执行时变量的加载顺序（优先级从高到低）：

```
1. 数据池参数（每轮不同）         ← 最高优先级
2. 响应提取变量（上一个节点提取）   ← 运行时动态
3. 链路级变量（chain scope）      ← 静态配置
4. 全局变量（global scope）       ← 最低优先级
```

同名变量高优先级覆盖低优先级。

## 三、模块一：登录兼容架构

### 3.1 登录方式分类

| 分类 | 登录方式 | 复杂度 | 实现方案 |
|------|---------|--------|---------|
| **简单 HTTP** | 静态 Token | 低 | AuthService（现有） |
| **简单 HTTP** | 用户名密码 POST 登录 | 低 | AuthService（现有，增强） |
| **简单 HTTP** | OAuth2 client_credentials | 低 | AuthService（现有 SSO） |
| **Cookie 会话** | 登录后靠 Cookie 维持会话 | 中 | AuthService 新增 COOKIE 类型 |
| **OAuth2 授权码** | 需要浏览器跳转授权 | 中 | AuthService 新增 OAUTH2_CODE 类型 |
| **CAS** | CAS 协议登录 | 中 | AuthService 新增 CAS 类型 |
| **复杂交互** | 有验证码的登录 | 高 | Playwright 浏览器引擎 |
| **复杂交互** | 有前端加密的登录 | 高 | Playwright 浏览器引擎 |
| **复杂交互** | SAML/SSO 多步跳转 | 高 | Playwright 浏览器引擎 |
| **复杂交互** | 企业微信/钉钉扫码登录 | 高 | Playwright + 人工辅助 |
| **兜底** | 以上都不适用 | — | 自定义脚本登录 |

### 3.3 轨道 A：AuthService 增强

**扩展 auth_type 枚举：**

```java
public enum AuthType {
    TOKEN,         // 静态 token（现有）
    PASSWORD,      // HTTP POST 登录（现有）
    SSO,           // OAuth2 client_credentials（现有）
    COOKIE,        // Cookie 会话登录（新增）
    OAUTH2_CODE,   // OAuth2 授权码流程（新增）
    CAS            // CAS 协议登录（新增）
}
```

**COOKIE 类型工作流：**
```
1. POST /login → 获取 Set-Cookie 响应
2. 解析 Set-Cookie → 提取 JSESSIONID / SESSION 等
3. 后续请求自动携带 Cookie: JSESSIONID=xxx
4. 支持 Cookie 过期自动重新登录
```

**OAUTH2_CODE 类型工作流：**
```
1. 打开浏览器 → 跳转到授权页
2. 用户授权 → 回调获取 authorization_code
3. 用 code 换取 access_token
4. 缓存 token，自动刷新
```

### 3.5 登录链路机制

**核心思路：登录本身就是一个 Chain。**

```
┌─────────────────────────────────┐
│     登录链路（Login Chain）       │
│  Node1: POST /auth/captcha      │
│  Node2: POST /auth/login        │
│  提取: $.data.token → __TOKEN__ │
│  提取: Set-Cookie → __SESSION__ │
└───────────────┬─────────────────┘
                │ login_chain_code 引用
                ↓
┌─────────────────────────────────┐
│     业务链路（Business Chain）    │
│  所有节点自动携带认证信息          │
│  Node1: POST /api/order/create  │
│  Node2: POST /api/order/pay     │
└─────────────────────────────────┘
```

**数据模型变更：**

```sql
ALTER TABLE test_chain
  ADD COLUMN login_chain_code VARCHAR(64) DEFAULT NULL 
    COMMENT '前置登录链路编码' 
    AFTER account_code,
  ADD COLUMN login_timeout INT DEFAULT 30000 
    COMMENT '登录超时(ms)' 
    AFTER login_chain_code;
```

**执行流程：**

```
1. 加载业务链路
2. 如果有 login_chain_code：
   a. 执行登录链路（同步）
   b. 提取登录链路的变量（token、cookie 等）
   c. 注入到业务链路的 ExecutionContext
3. 如果有 account_code：
   a. 获取账号 token（现有逻辑）
4. 合并所有变量（数据池 > 响应提取 > 链路变量 > 全局变量）
5. 执行业务节点
6. 记录结果
```

### 4.3 租户隔离实现：MyBatis 拦截器

**为什么用拦截器而不是改每个 Mapper？**

改每个 Mapper 意味着：
- 17 个 XML 文件都要改
- 每个 SELECT/UPDATE/DELETE 都要加 `WHERE tenant_id = ?`
- 新增 Mapper 时容易遗漏
- 维护成本高

用拦截器意味着：
- 一处配置，全局生效
- 新增表自动继承隔离
- 代码零侵入

**拦截器设计：**

```java
/**
 * 租户隔离拦截器
 * 
 * 工作原理：
 * 1. 拦截所有 SQL 执行
 * 2. 解析 SQL 中涉及的表名
 * 3. 如果表在"租户隔离白名单"中，自动注入 WHERE tenant_id = ?
 * 4. 如果表在"忽略名单"中，不过滤
 * 
 * 注意：这里是"白名单"机制——只有明确声明需要隔离的表才会被拦截。
 * 不是"黑名单"（排除不需要的），而是"白名单"（只包含需要的）。
 * 这样更安全：新表默认不过滤，必须显式声明才隔离。
 */
@Intercepts({...})
public class TenantInterceptor implements Interceptor {
    
    // 需要租户隔离的表（白名单）
    private static final Set<String> TENANT_TABLES = Set.of(
        "test_chain",
        "test_account", 
        "test_global_variable",
        "test_execute_main",
        "sys_category",
        "sys_scheduled_task",
        "sys_product",
        "test_data_pool"
    );
    
    // 完全忽略的表（全局数据，不隔离）
    private static final Set<String> IGNORE_TABLES = Set.of(
        "sys_tenant",      // 租户表本身
        "sys_config",      // 全局配置
        "sys_user",        // 用户表（已有自己的 tenant 过滤）
        "dict_category"    // 全局字典
    );
    
    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        // 1. 获取当前 SQL
        // 2. 解析表名
        // 3. 如果表在 TENANT_TABLES 中且不在 IGNORE_TABLES 中
        // 4. 获取当前用户 tenant_id（从 TenantContext）
        // 5. 注入 WHERE 条件
        // 6. 执行修改后的 SQL
    }
}
```

**租户上下文（ThreadLocal）：**

```java
public class TenantContext {
    private static final ThreadLocal<String> TENANT_ID = new ThreadLocal<>();
    
    public static void setTenantId(String tenantId) { TENANT_ID.set(tenantId); }
    public static String getTenantId() { return TENANT_ID.get(); }
    public static void clear() { TENANT_ID.remove(); }
}

// 在 JwtAuthFilter 中设置
@Override
protected void doFilterInternal(...) {
    String token = extractToken(request);
    if (token != null) {
        Claims claims = jwtUtil.parseToken(token);
        TenantContext.setTenantId(claims.get("tenantId", String.class));
    }
    try {
        filterChain.doFilter(request, response);
    } finally {
        TenantContext.clear();
    }
}
```

### 5.3 执行引擎改造

```java
/**
 * 参数化执行入口
 * 
 * @param chainCode 链路编码
 * @param roundIndex 轮次索引（从 0 开始），-1 表示不使用数据池
 * @param taskExecutionId 关联的定时任务执行 ID（可选）
 */
public String runChainWithParams(String chainCode, int roundIndex, String taskExecutionId) {
    // 1. 加载链路
    TestChain chain = chainMapper.selectByChainCode(chainCode);
    
    // 2. 创建 ExecutionContext
    ExecutionContext context = new ExecutionContext();
    
    // 3. 加载全局变量（修复现有 bug）
    Map<String, Object> globalVars = globalVariableService.loadVariableMap(chainCode);
    context.getVariables().putAll(globalVars);
    
    // 4. 执行登录链路（如果有）
    executeLoginChain(chain, context);
    
    // 5. 获取账号 token（如果有）
    obtainTokenForAccount(chain, context);
    
    // 6. 从数据池注入参数（如果有）
    if (roundIndex >= 0 && StringUtils.isNotBlank(chain.getDataPoolCode())) {
        Map<String, Object> poolVars = dataPoolService.getRowVars(chain.getDataPoolCode(), roundIndex);
        context.getVariables().putAll(poolVars);  // 数据池参数覆盖全局变量
    }
    
    // 7. 执行节点（现有逻辑）
    executeNodes(chain, context, ...);
}
```

**改造后的执行流程：**

```java
private void executeTask(Long taskId, String triggerType) {
    SysScheduledTask task = taskMapper.selectById(taskId);
    
    int roundCount = task.getRoundCount() != null ? task.getRoundCount() : 1;
    boolean useDataPool = task.getUseDataPool() != null && task.getUseDataPool() == 1;
    
    List<String> allExecutionIds = new ArrayList<>();
    
    for (int i = 0; i < roundCount; i++) {
        String executionId;
        if (useDataPool && StringUtils.isNotBlank(task.getDataPoolCode())) {
            // 参数化执行：每轮从数据池取不同行
            executionId = executeService.runChainWithParams(task.getChainCode(), i, null);
        } else {
            // 普通执行
            executionId = executeService.runChain(task.getChainCode());
        }
        allExecutionIds.add(executionId);
        
        // 轮次间隔
        if (i < roundCount - 1 && task.getRoundIntervalMs() > 0) {
            Thread.sleep(task.getRoundIntervalMs());
        }
    }
```

### 6.1 当前缺陷

| 缺陷 | 影响 |
|------|------|
| 无 `cookies` 权限 | 不能用 `chrome.cookies` API 读写 cookie |
| CDP 捕获默认关闭 | `extractAuthTokens()` 从不执行 |
| Cookie 名称白名单太窄 | 只识别 8 种常见 cookie 名 |
| 无 Cookie 持久化 | `capturedTokens` 在 service worker 重启后丢失 |
| 推送数据无 Cookie 字段 | 后端无法获取录制时的 cookie |
| HTTP 回放无 Cookie 注入 | 回放请求不携带 cookie |

### 6.2 改造方案

**manifest.json 新增权限：**

```json

  "permissions": ["storage", "sidePanel", "debugger", "activeTab", "tabs", "scripting", "cookies"],
  "host_permissions": ["<all_urls>"]
```

**Cookie 捕获增强：**

```javascript
// background.js — 增强 extractAuthTokens
function extractAuthTokens(data) {
    const { responseHeaders, url } = data;
    
    // 1. 解析 Set-Cookie（不限制 cookie 名称）
    const setCookie = responseHeaders['set-cookie'] || responseHeaders['Set-Cookie'];
    if (setCookie) {
        const cookies = parseSetCookie(setCookie, url);
        capturedTokens.cookies = capturedTokens.cookies || {};
        Object.assign(capturedTokens.cookies, cookies);
    }
    
    // 2. 提取 Authorization header（现有逻辑）
    // 3. 提取 URL 参数中的 token（现有逻辑）
    // 4. 从响应体提取 token（现有逻辑）
}

// 解析 Set-Cookie 并提取域名、路径、过期时间
function parseSetCookie(setCookieHeader, url) {
    const domain = new URL(url).hostname;
    const cookies = {};
    setCookieHeader.split(',').forEach(cookieStr => {
        const parts = cookieStr.trim().split(';');
        const [name, value] = parts[0].split('=');
        const cookie = {
            value: value?.trim(),
            domain: domain,
            path: getCookieAttr(parts, 'path') || '/',
            secure: parts.some(p => p.trim().toLowerCase() === 'secure'),
            httpOnly: parts.some(p => p.trim().toLowerCase() === 'httponly'),
            sameSite: getCookieAttr(parts, 'samesite') || 'Lax',
            expirationDate: getCookieExpiry(parts)
        };
        cookies[name.trim()] = cookie;
    });
    return cookies;
}
```

**Cookie 持久化：**

```javascript
// 保存到 chrome.storage.local
async function saveCapturedTokens() {
    await chrome.storage.local.set({ capturedTokens });
}

// 启动时恢复
chrome.runtime.onStartup.addListener(async () => {
    const data = await chrome.storage.local.get('capturedTokens');
    if (data.capturedTokens) Object.assign(capturedTokens, data.capturedTokens);
});
```

```javascript
        },
```

**HTTP 回放增加 Cookie 注入：**

```javascript
// sidepanel.js — httpReplay 中注入 cookie
async function httpReplay(api, authContext) {
    const headers = { ...api.headers };
    
    // 注入 cookie
    if (authContext?.cookies) {
        const cookieStr = Object.entries(authContext.cookies)
            .map(([name, cookie]) => `${name}=${cookie.value}`)
            .join('; ');
        headers['Cookie'] = cookieStr;
    }
    
    // 注入 token
    if (authContext?.tokens?.accessToken) {
        headers['Authorization'] = `Bearer ${authContext.tokens.accessToken}`;
    }
    
    return fetch(api.url, { method: api.method, headers, body: api.body });
}
```

## 八、字段规范

### 8.1 命名与编码规范

| 字段类型 | 规则 | 示例 |
|---------|------|------|
| `*_code` | 仅英文、数字、下划线、短横线，不区分大小写 | `tenant_001`, `PROD_ORDER` |
| `*_name` | 支持中英文、空格、特殊字符，UTF-8 | `北京科技有限公司`, `E-Commerce Platform` |
| `*_id` | BIGINT 自增或 VARCHAR(64) 编码 | `12345`, `tenant_001` |
| `*_url` | VARCHAR(512) | `https://sso.example.com/login` |
| `*_config` | JSON 类型 | `{"key": "value"}` |
| `*_description` | VARCHAR(512) 或 TEXT | 自由文本 |
| `status` | TINYINT, 1=启用, 0=禁用 | `1` |

|----|------|------|------|------|

| sys_tenant | tenant_name | VARCHAR | 256 | 中英文名称 |
| sys_product | product_code | VARCHAR | 64 | 英文标识 |
| sys_product | product_name | VARCHAR | 256 | 中英文名称 |

| test_account | account_name | VARCHAR | 256 | 中英文名称 |

### 8.4 中英文支持

- 所有 `*_name` 字段使用 `VARCHAR(256)` + `utf8mb4_unicode_ci`
- `utf8mb4_unicode_ci` 支持中文拼音排序
- 前端输入不限制字符集
- `*_code` 字段限制为 ASCII 字符（英文+数字+下划线+短横线）
- 数据库连接使用 `characterEncoding=utf8mb4`

## 十、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| MyBatis 拦截器对复杂 SQL 兼容性 | 租户过滤遗漏 | 白名单显式声明 + 全量 Mapper 测试 |
| Playwright 安装部署 | 服务器环境依赖 | Docker 镜像预装 + 降级方案（纯 HTTP 登录） |
| 登录链路同步执行阻塞 | 线程占用 | 设置超时 + Token 缓存减少重复登录 |
| 并发执行账号锁定 | 409 错误 | 账号池化 + 锁超时缩短 + 重试机制 |
| 大数据量数据池性能 | 查询慢 | 分页加载 + 索引优化 + 分表（未来） |
| 前端页面工作量大 | 开发周期长 | 复用现有组件模式 + 分批交付 |
