# 阶段一详细设计文档 - 插件核心增强

# 概述

阶段一解决插件录制的核心痛点：bizOperTraceId 生成与注入、时间滑动窗口过滤、三重过滤机制、录制按钮状态修复。不涉及后端改动。

涉及文件清单：
- plugin-test/inject.js（改造：新增 TraceId 注入 + 窗口状态感知 + DOM 事件触发）
- plugin-test/content.js（改造：新增窗口状态管理 + TraceId 传递）
- plugin-test/background.js（改造：新增 CDP 请求注入 TraceId + 窗口状态同步）
- plugin-test/sidepanel.js（改造：按钮三态 + 窗口状态指示器 + 分组展示）
- plugin-test/sidepanel.html（改造：新增状态指示器 UI + 分组折叠区域）
- plugin-test/manifest.json（改造：新增 cookies 权限）

# 一、bizOperTraceId 生成与注入

数据结构设计：

每个 bizOperTraceId 对象包含以下字段：
- traceId（string）：唯一标识，格式 biz_ + 时间戳 + 4位随机hex
- step（int）：当前步骤序号，每次用户操作递增
- pageUrl（string）：当前页面地址
- windowActive（boolean）：窗口是否处于 ACTIVE 状态
- createdAt（int）：创建时间戳
- expiresAt（int）：窗口过期时间戳

生成位置：
- background.js 中维护全局 currentTrace 对象
- 用户点击"开始录制"时生成第一个 Trace
- 每次用户交互触发时更新 step，不重新生成 traceId

注入流程：
1. inject.js 拦截 fetch 时，从 window.__AUTOTEST_BIZ_TRACE__ 读取当前 traceId
2. inject.js 拦截 XHR 时，同样从 window.__AUTOTEST_BIZ_TRACE__ 读取
3. 在请求头中追加 X-Biz-Oper-Trace: ${traceId}
4. 每条捕获的请求对象新增字段：bizOperTraceId、triggerEvent、targetDom、pageUrl、windowActive、ignore

inject.js 改造要点：

在现有 save() 函数中，新增以下字段到保存对象：
- bizOperTraceId：从 window.__AUTOTEST_BIZ_TRACE__.traceId 读取
- triggerEvent：从 window.__AUTOTEST_LAST_TRIGGER_EVENT__ 读取（click/change/keydown/submit/auto）
- targetDom：从 window.__AUTOTEST_LAST_TRIGGER_DOM__ 读取（DOM 选择器）
- pageUrl：location.href
- windowActive：从 window.__AUTOTEST_BIZ_TRACE__.windowActive 读取

在 fetch 拦截中：
- 在请求头中追加 X-Biz-Oper-Trace（仅当 window.__AUTOTEST_BIZ_TRACE__ 存在时）
- 需要 clone init.headers 避免修改原始对象

在 XHR 拦截中：
- 在 send() 前调用 setRequestHeader('X-Biz-Oper-Trace', traceId)
- 需要判断 readyState 确保在 open 之后、send 之前

DOM 事件监听改造：

新增全局 DOM 事件监听器，在 inject.js 中注册：
- click 事件：记录触发元素选择器到 window.__AUTOTEST_LAST_TRIGGER_DOM__
- change 事件：记录触发元素选择器
- keydown 事件：仅记录 Enter 键，记录触发元素选择器
- submit 事件：记录触发元素选择器

选择器生成逻辑：
- 优先使用 id：#elementId
- 其次使用 name：input[name="fieldName"]
- 再用 data-testid：[data-testid="testId"]
- 再用 class 组合：button.primary-btn
- 最后用 nth-of-type 兜底

# 二、时间滑动窗口 + 操作触发锁

状态机设计：

三种状态：IDLE、ACTIVE、封存

IDLE 状态：
- 录制已开始但用户未进行任何操作
- 窗口未激活，所有请求不归入任何链路
- 显示"等待操作..."提示

ACTIVE 状态：
- 用户触发交互事件（click/change/keydown/submit）
- 开启倒计时（默认 3 秒，可配置 2~5 秒）
- 窗口内收到新业务请求时重置倒计时
- 最长不超过 5 秒（可配置）
- 显示倒计时进度条

封存状态：
- 窗口超时，封存当前链路
- 将窗口内的请求归入当前 bizOperTraceId
- 返回 IDLE 状态，等待下一次操作

background.js 新增状态管理：

新增变量：
- windowState：'IDLE' | 'ACTIVE'
- currentTrace：{ traceId, step, pageUrl, windowActive, createdAt, expiresAt }
- windowTimer：setTimeout 引用
- maxWindowMs：最大窗口时长（默认 5000）
- windowMs：单次窗口时长（默认 3000）

处理交互事件消息：
- content.js 发送 TRIGGER_INTERACTION 消息到 background.js
- background.js 收到后：
  - 如果是 IDLE 状态 → 生成新 traceId，设为 ACTIVE，启动倒计时
  - 如果是 ACTIVE 状态 → 重置倒计时（但不重新生成 traceId）
  - 将当前 currentTrace 广播给所有 tab 的 inject.js

倒计时逻辑：
- 每次启动/重置倒计时，设置 windowTimer = setTimeout(封存, windowMs)
- 收到新业务请求时：clearTimeout(windowTimer)，重新 setTimeout(封存, windowMs)
- 但总时长不超过 maxWindowMs：如果 Date.now() - currentTrace.createdAt >= maxWindowMs，直接封存
- 封存时：将 windowActive 设为 false，清空 currentTrace

content.js 新增交互事件转发：

在宏录制器的事件处理函数中，新增消息发送：
- onClick：发送 TRIGGER_INTERACTION { type: 'click', selector, pageUrl }
- onChange：发送 TRIGGER_INTERACTION { type: 'change', selector, pageUrl }
- onKeydown（Enter）：发送 TRIGGER_INTERACTION { type: 'keydown', selector, pageUrl }
- onSubmit：发送 TRIGGER_INTERACTION { type: 'submit', selector, pageUrl }

消息格式：
{
  type: 'TRIGGER_INTERACTION',
  interactionType: 'click' | 'change' | 'keydown' | 'submit',
  selector: '元素选择器',
  pageUrl: '当前页面URL',
  timestamp: Date.now()
}

inject.js 窗口状态同步：

background.js 通过 postMessage 将窗口状态同步到 inject.js：
- 消息类型：AUTOTEST_BIZ_TRACE_UPDATE
- 携带 traceId、windowActive、expiresAt
- inject.js 更新 window.__AUTOTEST_BIZ_TRACE__ 对象

# 三、三重过滤机制

第一重：黑白名单过滤（已有，保留）
- inject.js 和 background.js 中的 shouldCapture() 逻辑不变
- 静态资源、埋点上报、自定义黑名单/白名单继续生效

第二重：时间窗口过滤（新增）

在 inject.js 的 save() 函数中新增判断：
- 如果 window.__AUTOTEST_BIZ_TRACE__ 不存在 → 丢弃（未开始录制操作）
- 如果 window.__AUTOTEST_BIZ_TRACE__.windowActive === false → 丢弃（窗口已关闭）
- 如果 window.__AUTOTEST_BIZ_TRACE__.expiresAt < Date.now() → 丢弃（窗口已过期）
- 只有 windowActive === true 且未过期的请求才保存

在 background.js 的 saveApi() 函数中同样新增判断：
- 检查 currentTrace 是否存在且 ACTIVE
- 如果不是 ACTIVE 状态，不保存该请求

自动延长窗口：
- 在 save() 或 saveApi() 中，如果请求被成功保存（窗口 ACTIVE），通知 background.js 重置倒计时
- 通过 postMessage 发送 WINDOW_EXTEND 消息
- background.js 收到后 clearTimeout + setTimeout 重置

第三重：手动标记过滤（新增）

在 sidepanel.js 的 render() 函数中：
- 每条请求增加 ignore 字段展示
- 可疑请求（通过 heuristic 判断）标灰显示
- 用户可点击取消勾选，设置 ignore: true

可疑请求判断规则：
- URL 中包含 poll/refresh/heartbeat/cron 等关键词 → 标记为"疑似轮询"
- 相同 URL 在 5 秒内出现 3 次以上 → 标记为"疑似定时请求"
- apiType 为 'track' 但未被第一重过滤 → 标记为"疑似埋点"
- 响应体为空或仅包含状态码 → 标记为"疑似心跳"

# 四、录制按钮状态修复

当前问题分析：
- sidepanel.js 中按钮通过 classList.contains('btn-stop') 判断状态
- 点击后直接切换 class 和文本，但 background.js 的状态可能不同步
- 停止录制后按钮无视觉反馈，用户无法确认是否停止

修复方案：

三态设计：
- 未录制：灰色按钮，文本"录制接口"
- 录制中：红色按钮（btn-stop），文本"停止录制"，带脉冲动画
- 已停止：绿色按钮（btn-stopped），文本"已停止 ✓"，2 秒后恢复为"录制接口"

状态同步机制：
- sidepanel.js 发送 START_RECORDING/STOP_RECORDING 后，等待 background.js 回调
- background.js 的消息处理已返回 sendResponse({ ok: true })
- sidepanel.js 在收到响应后更新按钮状态

具体改造：

sidepanel.js 的 recordApiBtn 点击事件：
1. 发送消息到 background.js
2. 设置按钮为"加载中"状态（禁用 + 转圈图标）
3. 在 sendResponse 回调中更新按钮状态
4. 如果是停止操作，设置 2 秒定时器恢复为"录制接口"

新增 CSS 类：
- .btn-stopped：绿色背景，白色文字
- .btn-pulse：脉冲动画（录制中状态）
- .btn-loading：禁用 + 转圈

窗口状态指示器：
- sidepanel 顶部新增状态指示器
- 显示当前窗口状态：IDLE（灰色）/ ACTIVE（绿色闪烁）
- 显示当前 TraceId（截断显示）
- 显示倒计时进度条（ACTIVE 时）

# 五、sidepanel 分组展示

录制面板改造：

当前 sidepanel.js 的 render() 函数按时间顺序展示所有请求。
改造为按 bizOperTraceId 分组展示：

分组逻辑：
1. 从 apis 数组中提取所有不同的 bizOperTraceId
2. 按 bizOperTraceId 创建分组，每组包含：
   - 分组标题：显示 traceId + 触发事件类型 + 页面地址
   - 分组内请求列表
3. 未归入任何分组的请求（windowActive=false）显示在"未分组"区域

分组标题栏：
- 显示 TraceId（截断为 biz_1718...a3f2）
- 显示触发事件图标（click/change/keydown/submit）
- 显示页面地址
- 折叠/展开按钮
- 全选/取消全选按钮

分组内请求：
- 每条请求显示：方法、URL（截断）、状态码、耗时
- 复选框：默认勾选，用户可取消
- ignore 字段：可疑请求标灰

UI 交互：
- 分组默认展开，用户可折叠
- 分组内全选/取消全选
- 分组间独立操作
- 推送时按分组推送，每组生成一条独立链路

# 七、数据流完整链路

完整录制流程：
1. 用户点击"录制接口"按钮
2. sidepanel.js 发送 START_RECORDING 到 background.js
3. background.js 设置 isRecording=true，广播 START_RECORDING 到所有 content.js
4. content.js 通知 inject.js 开始录制（postMessage AUTOTEST_RECORDING_STATE）
5. inject.js 设置 isRecording=true，注册 DOM 事件监听器
6. background.js 生成第一个 bizOperTraceId，广播 AUTOTEST_BIZ_TRACE_UPDATE

用户操作流程：
1. 用户在页面点击按钮
2. inject.js 的 click 监听器捕获事件
3. 记录触发元素选择器到 window.__AUTOTEST_LAST_TRIGGER_DOM__
4. 通过 content.js 发送 TRIGGER_INTERACTION 到 background.js
5. background.js 收到后，如果 IDLE → 生成新 traceId，设为 ACTIVE
6. background.js 广播 AUTOTEST_BIZ_TRACE_UPDATE 到所有 tab
7. inject.js 收到更新，设置 windowActive=true
8. 页面发起的请求被 inject.js 拦截
9. inject.js 检查 windowActive=true，注入 X-Biz-Oper-Trace 头，保存请求
10. background.js 的 CDP 捕获同样检查 windowActive，注入 TraceId
11. 倒计时结束后，background.js 设为 IDLE，窗口关闭
12. 下次用户操作时，重复步骤 1-11，生成新的 bizOperTraceId

停止录制流程：
1. 用户点击"停止录制"按钮
2. sidepanel.js 发送 STOP_RECORDING 到 background.js
3. background.js 设为 IDLE，清理定时器
4. 广播 STOP_RECORDING 到所有 content.js
5. content.js 通知 inject.js 停止录制
6. inject.js 清理所有状态
7. background.js detach 所有 debugger
8. sidepanel.js 更新按钮为"已停止"状态，2 秒后恢复

# 八、与现有代码的兼容性

inject.js 改造兼容：
- 新增的字段（bizOperTraceId 等）在 save() 中追加，不影响原有字段
- 窗口状态判断在 save() 开头，未开始录制时行为与原来一致
- DOM 事件监听器在 isRecording=true 时才注册，不影响页面性能

content.js 改造兼容：
- TRIGGER_INTERACTION 消息在宏录制器事件处理函数中追加发送
- 不修改宏录制器原有逻辑
- 窗口状态消息在 onMessage 中新增处理

background.js 改造兼容：
- 状态管理变量在现有 isRecording 基础上扩展
- 消息处理新增 TRIGGER_INTERACTION 和 WINDOW_EXTEND 类型
- saveApi() 中新增窗口状态判断，不影响原有保存逻辑
- 倒计时逻辑独立，不影响现有 CDP 捕获流程

sidepanel.js 改造兼容：
- 按钮状态改为三态，通过回调确认状态切换
- 分组展示为新增函数，原有 render() 逻辑保留
- 新增状态指示器 UI，不影响现有 Tab 切换

# 九、测试验证点

功能验证：
1. 开始录制后，未操作时不应捕获任何请求
2. 点击页面按钮后，3 秒内的请求应归入当前 TraceId
3. 3 秒后窗口关闭，新请求不应归入当前 TraceId
4. 再次点击按钮，应生成新的 TraceId
5. 两条 TraceId 的请求不应混在一起
6. 停止录制后，按钮应显示"已停止"并 2 秒后恢复
7. 推送时应按 TraceId 分组推送
8. 未归入分组的请求应显示在"未分组"区域

兼容性验证：
1. 不开启时间窗口时，行为应与改造前一致
2. 旧版本推送的数据（无 bizOperTraceId）应正常显示
3. 页面刷新后 inject.js 应重新注入
4. 多 tab 场景下每个 tab 的窗口状态应独立
