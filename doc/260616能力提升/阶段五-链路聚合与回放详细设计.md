# 阶段五详细设计文档 - 前后端链路聚合与回放

# 概述

阶段五完成最终目标：以 bizOperTraceId 为分组主键聚合前后端全链路，按 TraceId 分组回放纯净业务用例。

涉及文件清单：
- backend 改造：service/impl/ChainServiceImpl.java（TraceId 聚合查询）
- backend 改造：service/impl/ExecuteServiceImpl.java（TraceId 分组回放）
- backend 改造：controller/ChainController.java（聚合查询接口）
- frontend/src/views/ChainEdit.vue（改造：TraceId 分组视图）
- frontend/src/views/ExecuteDetail.vue（改造：TraceId 分组回放展示）
- plugin-test/sidepanel.js（改造：分组推送改造）

# 一、TraceId 聚合查询

聚合逻辑：
- 以 bizOperTraceId 作为分组主键
- 查询 test_node_config 表，按 bizOperTraceId 分组
- 每组包含：traceId、触发事件、页面地址、节点列表（按 sortNo 排序）
- 未归入任何分组的节点（bizOperTraceId 为空）单独分组

查询接口：
- GET /api/chain/trace-groups?chainCode={chainCode}
- 返回：List<TraceGroupVO>
- TraceGroupVO 包含：traceId、triggerEvent、pageUrl、nodeCount、nodes

# 二、TraceId 分组回放

回放流程：
1. 获取链路的所有 TraceGroup
2. 按 TraceGroup 顺序回放（串行）或并行回放
3. 每个 TraceGroup 内的节点按 sortNo 串行执行
4. 每个 TraceGroup 独立的变量上下文
5. 每个 TraceGroup 独立的断言验证

回放配置：
- 回放模式选择：
  - 全链路回放：按 TraceGroup 顺序依次回放
  - 单组回放：选择特定 TraceGroup 回放
  - 并发回放：多个 TraceGroup 并发执行
- 每个 TraceGroup 可独立配置：
  - 是否执行
  - 账号绑定
  - 超时时间
  - 失败策略

回放结果展示：
- 按 TraceGroup 分组展示执行结果
- 每组显示：TraceId、执行状态、耗时、成功/失败节点数
- 组内节点显示：执行状态、请求/响应、耗时、断言结果
- 总体统计：总 TraceGroup 数、成功组数、失败组数

# 三、分组推送改造

插件推送改造：
- sidepanel.js 的 doPush() 函数改造
- 按 bizOperTraceId 分组推送，每组生成独立链路
- 链路命名规则：{页面路径}_{触发事件}_{时间戳}
- 未分组的 ignore 请求不推送

推送数据结构：
{
  chainName: "用户管理_click_20260616",
  bizOperTraceId: "biz_1718544000000_a3f2",
  triggerEvent: "click",
  pageUrl: "https://app.company.com/user/list",
  interfaceList: [...]
}

后端处理：
- PluginController.createChainByPlugin 改造
- 接收 bizOperTraceId 字段
- 存储到 test_chain 和 test_node_config 表
- 返回创建的链路信息

# 四、ChainEdit 分组视图

新增分组视图模式：
- 在现有列表视图基础上，新增"分组视图"切换按钮
- 分组视图：按 TraceGroup 分组展示节点
- 每个分组显示：TraceId、触发事件、页面地址、节点列表
- 分组间可拖拽调整顺序
- 分组内节点可拖拽调整顺序

分组操作：
- 新增分组：手动创建空分组
- 删除分组：删除分组及其所有节点
- 合并分组：将两个分组合并
- 拆分分组：从分组中拆出节点创建新分组

# 五、ExecuteDetail 分组展示

执行结果分组展示：
- 在现有执行详情基础上，按 TraceGroup 分组展示
- 每个分组显示：TraceId、执行状态、耗时、节点执行结果
- 分组状态：成功（绿色）、失败（红色）、跳过（灰色）
- 点击分组展开查看节点详情

执行统计：
- 总分组数、成功分组数、失败分组数、跳过分组数
- 总耗时、平均每组耗时
- 失败分组的失败原因汇总

# 六、数据流完整链路

录制到回放完整流程：
1. 用户在浏览器操作，插件录制请求
2. 每次操作生成 bizOperTraceId，请求携带该 ID
3. 录制结束，按 TraceId 分组推送到后端
4. 后端存储链路和节点，关联 TraceId
5. 用户在前端查看链路，按 TraceGroup 分组展示
6. 用户配置回放参数，绑定测试账号
7. 执行回放，按 TraceGroup 顺序回放
8. 每个 TraceGroup 独立执行，独立断言
9. 执行结果按 TraceGroup 分组展示
10. 用户查看结果，分析失败原因
