# 一、BizOperTraceFilter 拦截器

职责：
- 从请求头 X-Biz-Oper-Trace 提取操作级 TraceId
- 存入 ThreadLocal，供后续 Feign/MyBatis 调用透传
- 请求结束时清理 ThreadLocal

实现要点：
- 继承 OncePerRequestFilter
- 过滤路径：/api/**
- 在 doFilterInternal 中：
  1. 从 request.getHeader("X-Biz-Oper-Trace") 提取值
  2. 如果非空，存入 BizOperTraceContext.setTraceId(traceId)
  3. 调用 filterChain.doFilter()
  4. finally 中调用 BizOperTraceContext.clear()

BizOperTraceContext 工具类：
- 静态方法 setTraceId(String traceId)
- 静态方法 getTraceId() → String
- 静态方法 clear()
- 内部使用 ThreadLocal<String>

注册方式：
- 在主启动类 AutoTestApplication 中注册 @Bean FilterRegistrationBean<BizOperTraceFilter>
- 设置 order 为最高优先级（Ordered.HIGHEST_PRECEDENCE）
- 设置 urlPatterns 为 /api/*

# 七、测试账号管理模块

数据模型 TestAccount 实体：
- id、accountCode、accountName、systemName、username、password
- authType、authConfig、status、lastUsedTime、lockUntil
- createTime、updateTime

密码加密：
- 使用 AES 加密存储，密钥从配置文件读取
- 读取时自动解密
- 新增工具类 AESUtil：encrypt(String data, String key)、decrypt(String encrypted, String key)

AccountService 接口方法：
- createAccount(AccountCreateDTO dto) → TestAccount
- updateAccount(Long id, AccountCreateDTO dto) → TestAccount
- deleteAccount(Long id)
- getAccount(Long id) → TestAccount
- listAccounts(String systemName, Integer status) → List<TestAccount>
- acquireAccount(String accountCode) → TestAccount（获取可用账号并锁定）
- releaseAccount(String accountCode)（释放账号锁定）
- batchLock(String accountCode, int minutes)（批量锁定账号）

账号锁定逻辑：
- acquireAccount 时检查 status 和 lock_until
- 如果 status=1 且 lock_until 为 null 或已过期 → 设为 status=2，lock_until=当前时间+30分钟，返回账号
- 如果 status=2 且 lock_until > 当前时间 → 抛出"账号已被占用"
- 如果 status=2 且 lock_until <= 当前时间 → 自动解锁，重新获取
- releaseAccount 时设为 status=1，lock_until=null

账号认证配置 auth_config JSON 格式：
SSO 类型：

  "ssoServiceUrl": "https://app.company.com",

  "clientId": "test-client",
  "clientSecret": "test-secret"
}

PASSWORD 类型：
{
  "loginUrl": "https://app.company.com/api/login",
  "loginMethod": "POST",

# 十、执行引擎改造（预留）

ExecuteServiceImpl 改造点：
- 执行链路前，根据 chain 的 accountCode 获取测试账号
- 如果账号 authType=SSO，先调用 SSO 登录接口获取 token
- 如果账号 authType=PASSWORD，先调用登录接口获取 token
- 将 token 存入 ExecutionContext 的变量中
- 后续节点的 Authorization 头自动注入 token
- 执行完成后释放账号锁定

账号自动注入：
- 在 ExecutionContext 中新增变量 __ACCOUNT_TOKEN__
- 在 ExecuteServiceImpl.executeNode() 中，如果请求头包含 Authorization 且值为 ${__ACCOUNT_TOKEN__}，自动替换为实际 token
- 如果请求头中没有 Authorization 但 chain 绑定了账号，自动添加 Authorization: Bearer ${__ACCOUNT_TOKEN__}

# 十一、测试验证点

Filter 验证：
1. 请求头携带 X-Biz-Oper-Trace 时，ThreadLocal 中应有值
2. 请求头不携带时，ThreadLocal 为 null
3. 请求结束后 ThreadLocal 应被清理
4. 并发请求时 ThreadLocal 不会互相干扰

数据库验证：
1. 插件推送时新字段应正确入库
2. 旧数据新字段应为 null，不影响查询
3. 分类筛选应正确返回结果

账号管理验证：
1. 创建账号时密码应加密存储
2. 获取账号时应正确锁定
3. 释放账号后应可再次获取
4. 并发获取同一账号时应只有一个成功
5. 锁定超时后应自动解锁
