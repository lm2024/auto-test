# 详细设计文档 v1.0 - 测试链路管理模块

## 1. 模块概述

测试链路管理模块是平台的顶层业务单元，负责测试链路的增删改查、执行模式配置、链路复制与版本管理、以及浏览器插件新建链路等核心功能。一条链路对应一个完整的测试流程，所有节点配置作为链路模板存储于数据库。

## 3. 数据库设计

## 4. 核心流程设计

### 4.1 链路创建流程

```mermaid
flowchart TD
    A[前端提交链路创建请求] --> B{参数校验}
    B -->|校验失败| C[返回错误信息]
    B -->|校验通过| D[生成唯一链路编码]
    D --> E{编码是否已存在}
    E -->|已存在| D
    E -->|不存在| F[插入test_chain表]
    F --> G{插入成功?}
    G -->|失败| H[事务回滚, 返回错误]
    G -->|成功| I[返回链路ID与编码]
    C --> J[前端提示用户]
    I --> K[前端跳转链路列表]
```

**编码生成规则:**
- 格式: `CHAIN_` + 8位时间戳后6位 + 4位随机数
- 示例: `CHAIN_240612A3F7B2E1`
- 生成后查询唯一索引校验，冲突则重新生成

### 4.2 链路复制流程

```mermaid
flowchart TD
    A[用户点击复制按钮] --> B[查询原链路所有节点配置]
    B --> C[生成新链路编码<br/>原编码_副本N]
    C --> D[插入新test_chain记录]
    D --> E[遍历节点列表]
    E --> F[插入新test_node_config记录<br/>node_id重新分配]
    F --> G{还有节点?}
    G -->|是| E
    G -->|否| H[事务提交]
    H --> I[返回新链路ID、编码、节点列表]
```

### 4.3 插件新建链路流程

```mermaid
flowchart TD
    A[插件POST /api/plugin/chain/create] --> B{参数合法性校验}
    B -->|失败| C[返回400错误]
    B -->|成功| D[生成链路编码]
    D --> E[创建test_chain记录<br/>execute_mode=1 全串行]
    E --> F[遍历接口列表]
    F --> G[批量插入test_node_config]
    G --> H[按录制顺序赋值sort_no]
    H --> I[自动识别参数依赖]
    I --> J{前序响应字段<br/>与后序入参字段<br/>是否匹配?}
    J -->|是| K[自动生成变量提取规则<br/>生成占位符引用]
    J -->|否| L[无依赖关系]
    K --> M{还有接口?}
    L --> M
    M -->|是| G
    M -->|否| N[返回链路ID、编码、<br/>节点列表、参数关联关系]
```

### 4.4 参数依赖自动识别算法

```mermaid
flowchart TD
    A[获取链路所有节点<br/>按sort_no排序] --> B[遍历相邻节点对<br/>前序节点P, 后序节点Q]
    B --> C[从P的responseData<br/>提取所有叶子字段路径]
    C --> D[从Q的body_data<br/>提取所有入参字段路径]
    D --> E{字段名精确匹配?}
    E -->|是| F[建立依赖关系<br/>P.field -> Q.field<br/>生成提取规则与占位符]
    E -->|否| G{语义匹配?<br/>字段名转换后一致?}
    G -->|是| F
    G -->|否| H[无依赖关系]
    F --> I{还有节点对?}
    H --> I
    I -->|是| B
    I -->|否| J[返回所有依赖关系列表]
```

**语义匹配规则:**
- 下划线转驼峰: `order_id` <-> `orderId`
- 驼峰转下划线: `orderId` <-> `order_id`
- 大小写不敏感比较
- 支持常见缩写映射

## 6. 执行模式设计

### 6.1 全串行模式

```mermaid
flowchart LR
    A[节点1<br/>sort_no=1] --> B[节点2<br/>sort_no=2]
    B --> C[节点3<br/>sort_no=3]
    C --> D[节点4<br/>sort_no=4]
```

- 所有节点按 sort_no 从小到大依次执行
- 前序节点失败，后续所有节点标记为「跳过」
- 无并行分组标识（parallel_group 为空）

### 6.2 分组并行模式

```mermaid
flowchart TD
    subgraph 第1组[串行组1]
        A[节点1<br/>group=A]
        B[节点2<br/>group=A]
    end
    A & B --> C{组1全部完成?}
    C -->|是| D[第2组<br/>组串行开始]
    C -->|否| E[终止后续所有组]
    
    subgraph 第2组[串行组2]
        F[节点3<br/>group=B]
        G[节点4<br/>group=B]
    end
```

- 同 parallel_group 标识的节点并行执行
- 组与组之间按组内最小 sort_no 串行排序
- 单组内任意节点失败，标记本组失败，终止后续所有组

## 7. 异常处理

| 异常场景 | 处理方式 | 返回码 |
|----------|----------|--------|
| 链路编码已存在 | 拒绝创建，提示编码冲突 | 409 |
| 删除链路但节点被引用 | 级联删除关联节点 | 200 |
| 插件推送数据格式错误 | 拒绝写入，返回具体错误 | 400 |
| 数据库写入失败 | 事务回滚，返回500 | 500 |
| 参数依赖识别失败 | 降级为无依赖关系，不中断流程 | 200 + 警告 |

## 8. 关键技术点

### 8.1 JDK 8 兼容性

- 不使用 Java 9+ 的 var、switch表达式、records 等语法
- 使用 `java.util.Date` 和 `java.sql.Timestamp` 做时间处理
- JSON 序列化使用 Fastjson（与 LangChain4j 0.35.0 兼容）

### 8.2 事务管理

```java
@Transactional(rollbackFor = Exception.class)
public ChainVO createChain(ChainCreateDTO dto) {
    // 1. 生成并校验链路编码
    String chainCode = generateChainCode();
    
    // 2. 插入test_chain
    testChainMapper.insert(buildChain(dto, chainCode));
    
    // 3. 批量插入节点（插件场景）
    if (dto.getNodeList() != null) {
        batchInsertNodes(dto.getNodeList(), chainCode);
    }
    
    return buildChainVO(chainCode);
}
```

### 8.3 参数依赖识别

- 递归提取 JSON 响应中的所有叶子字段路径
- 与后续节点请求体字段做精确匹配和语义匹配
- 匹配成功后自动注入提取规则和占位符
