# 产品定位文档

## 一、项目概述

本项目是一套**轻量化内网接口自动化测试平台**，由三大模块组成：

| 模块 | 技术栈 | 核心职责 |
|------|--------|----------|
| 浏览器插件（接口录制助手） | Manifest V3 + 原生JS | 页面接口录制、参数依赖识别、一键推送平台 |
| 前端可视化平台 | Vue 3 + Vite + Element Plus + LogicFlow | 可视化流程编排、执行状态展示、AI功能交互 |
| 后端服务 | JDK 8 + Spring Boot 2.7.7 + MySQL 5.7 + LangChain4j | 链路管理、执行引擎、日志存储、AI能力 |

**完整业务闭环：**
```
安装插件 → 开启录制 → 操作业务页面 → 插件自动捕获接口 → 一键推送至平台
→ 自动生成测试链路 + 参数关联 → 画布调整流程 → AI生成测试数据
→ 触发执行 → 实时查看节点状态 → 失败节点一键AI分析
```

## 二、测试类型定位

### 2.1 对被测系统（SUT）的测试

本项目对被测系统采用**黑盒 + 端到端（E2E）自动化测试**方法。测试团队对被测系统内部实现完全不了解，只关注输入输出。

覆盖的测试类型：

| 测试类型 | 说明 | 本项目适用性 |
|---------|------|-------------|
| **冒烟测试** | 新版本部署后快速验证核心功能是否正常 | ✅ 插件录制核心链路，一键执行验证 |
| **回归测试** | 确保修改后不破坏现有功能，自动化测试的主要价值 | ✅ 链路模板存储，重复执行回归 |
| **功能测试** | 验证各功能是否符合需求 | ✅ 节点级断言规则校验 |
| **API测试** | 测试接口功能、参数传递、响应格式 | ✅ 本项目核心能力 |
| **版本对比测试** | 不同版本间接口行为差异检测 | ✅ 插件已有版本对比能力 |
| **链路测试** | 多接口串联的业务流程测试 | ✅ 核心卖点，参数自动依赖识别 |

### 2.2 对测试项目本身的测试

本项目作为软件产品，同样需要质量保证：

| 测试类型 | 适用模块 | 建议 |
|---------|---------|------|
| **单元测试** | 后端Service/工具类、前端组件 | JUnit + Vitest，保证核心逻辑正确 |
| **集成测试** | 后端Controller、插件与平台交互 | MockMvc + 接口联调测试 |
| **端到端测试** | 前端页面、插件完整流程 | Playwright/Cypress 模拟用户操作 |
| **冒烟测试** | 部署后快速验证 | 核心链路执行一次，确认平台可用 |

### 2.3 测试方法论

本项目采用**黑盒测试**方法：

- 测试人员不了解被测系统内部实现
- 基于需求规格、用户故事、接口文档设计测试用例
- 只关注输入（请求参数）和输出（响应结果）
- 通过断言规则验证系统行为是否符合预期

## 三、产品命名方案

### 3.1 命名原则

- 简洁易记，2-3个音节为佳
- 体现核心能力（录制、链路、编排、AI）
- 中英文均可，但需统一品牌
- 避免与现有知名产品重名

### 3.2 英文名推荐

| 名称 | 含义 | 亮点 |
|------|------|------|
| **ApiCraft** | API工匠 — 录制、编排、打磨接口测试 | 简洁有力，国际化，有质感 |
| **ChainForge** | 链路熔炉 — 构建、锻造测试链路 | 突出"链路"核心概念 |
| **LinkShot** | 链路一击 — 录制即链路，一键执行 | 突出"录制→执行"的快速感 |
| **TestPilot** | 测试领航 — AI驱动的自动化测试 | 突出AI和引导感 |
| **ApiWeaver** | API织网 — 编排、编织测试流程 | 突出可视化编排能力 |

### 3.3 中文名推荐

| 名称 | 说明 | 推荐理由 |
|------|------|---------|
| **链测** | 链路测试 | 简洁好记，突出核心概念"链路" |
| **录测** | 录制+测试 | 突出插件录制能力，差异化明显 |
| **智测** | 智能测试 | 突出AI能力，但较通用 |

### 3.4 推荐方案

**首选：ApiCraft / 链测**

- ApiCraft：英文场景下简洁、有工匠精神的品牌感，适合技术团队传播
- 链测：中文场景下直接点明核心能力（链路测试），好记好传播

**备选：ChainForge / 录测**

- ChainForge：强调链路构建能力，"Forge"有锻造、打造的意象
- 录测：突出"录制"这一差异化能力，与竞品形成区隔

## 四、与竞品对比定位

| 维度 | Postman | Apifox | JMeter | 本项目（ApiCraft/链测） |
|------|---------|--------|--------|------------------------|
| 录制能力 | 需手动导入 | 支持录制 | 需手动录制 | ✅ 浏览器插件一键录制 |
| 链路编排 | 无 | 基础 | 脚本编写 | ✅ 可视化拖拽画布 |
| 参数依赖 | 手动配置 | 部分自动 | 脚本编写 | ✅ 自动识别+人工微调 |
| AI能力 | 有（云端） | 有 | 无 | ✅ 内网离线AI |
| 内网部署 | 支持 | 支持 | 支持 | ✅ 纯内网，零外网依赖 |
| 上手门槛 | 中等 | 中等 | 高 | ✅ 零编码，30分钟上手 |

**核心差异化：**
1. **录制即链路** — 插件录制后自动识别参数依赖，一键生成完整测试链路
2. **纯内网AI** — 基于LangChain4j对接内网大模型，数据不出网
3. **可视化编排** — 拖拽式画布，普通测试人员无需编码
4. **零中间件** — 单实例部署，无Redis/MQ，运维成本极低
