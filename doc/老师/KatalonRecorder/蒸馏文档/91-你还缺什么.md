## 3. 需要你拍板的决策题

**这是全篇最重要的部分。** 下面每题都会影响你的架构，越早定越省事。我给了推荐答案和理由。

### D1 · 用什么技术栈？

| 选项 | 工作量 | 推荐 |
|---|---|---|
| A. 裸 JS（跟 KR 一样） | 最小 | ❌ 命令模型和消息协议没有类型约束，改一处炸三处 |
| B. **TypeScript + Vite + @crxjs** | +1 天搭环境 | ✅ **推荐**。你是 Java 背景，TS 的类型系统对你是舒适区不是负担 |
| C. TS + React 全家桶 | +3 天 | ⚠️ Panel 是个表格 + 日志，React 有点重，但你若熟就上 |

> **Java 类比**：选 A 相当于用 Map<String,Object> 传参写整个系统；选 B 相当于定义 POJO。你懂的。

### D2 · 后台放哪？

**这题其实没得选，但必须你自己认同。**

放 **Panel 独立窗口**（`chrome.windows.create({type:"popup"})`），不放 Service Worker。理由见 00 号文档 §2 那张表：SW 30 秒被杀、没 DOM、没 `window.prompt()`。

唯一的代价：**用户关掉 Panel 窗口 = 录制状态全丢**。KR 就是这样，接受它。

### D3 · 要不要文件上传（`<input type="file">`）？

| 选项 | 代价 |
|---|---|
| 要 | 必须申请 `debugger` 权限，用 CDP `DOM.setFileInputFiles`。**浏览器顶部会常驻一条"正在被调试"的黄色横幅**，很丑，且上架审查会被重点关注 |
| 不要 | 遇到文件上传场景手工介入 |

> 推荐：**先不要**。等真的被这个场景卡住了再加，代码就 30 行（`background/kar.js:174-192`）。

### D4 · 要不要特殊按键（Tab / Enter / 方向键）？

同样依赖 `debugger`（CDP `Input.dispatchKeyEvent`）。但**大部分场景可以用合成事件绕过**（`dispatchEvent(new KeyboardEvent(...))`），只有需要触发浏览器原生行为（比如 Tab 切焦点）时才必须 CDP。

> 推荐：**先用合成事件**，和 D3 共用一个 `debugger` 权限开关。

### D5 · 要不要 Self-healing 自愈？

> 推荐：**要**。这是投入产出比最高的一个功能——核心逻辑 `getPossibleTargetList` 只有 22 行，但能让"页面改了个 class 名，脚本全挂"变成"自动切到备用定位器继续跑"。

前提是你在录制时就得**存多候选定位器**（`.krecorder` 的 `<datalist>` 设计就是为这个服务的），所以 D5 = 要，就意味着存档格式必须用 `.krecorder` 那套。

### D6 · 存档格式用什么？

| 选项 | 优点 | 缺点 |
|---|---|---|
| A. **`.krecorder`（HTML 表格 + datalist + data-tags）** | 人可读、浏览器直接打开就能看、与 Selenium IDE 生态兼容、天然装得下多候选定位器 | 解析要用 DOMParser |
| B. JSON | 好解析 | 不可读、生态孤岛 |
| C. `.side`（Selenium IDE 官方格式） | 生态最广 | 装不下候选定位器和 tags |

> 推荐：**A**，理由是它同时满足"人可读 + 机器可解析 + 生态兼容"。这是 KR 少数几个设计得非常漂亮的地方（`parser.js`，全文只有 144 行）。

### D7 · 导出几种语言？

> 推荐：**先做 1 种，最多 2 种**。用新式纯函数契约 `(name, commands) => {content, extension, mimetype}`，每种 50-80 行。
>
> 选哪种取决于你团队用什么。如果没有历史包袱，**Playwright (JS/TS)** 是当下最好的落点；如果要接 Python 生态，**pytest + Selenium**。
>
> **坚决不要**碰旧式那套全局函数层叠体系（19 种语言、300 KB、调试时根本不知道是哪个文件覆盖了 `formatCommand`）。

### D8 · 要不要 iframe 支持？

> 推荐：**MVP-1 不要，MVP-2 一定要**。
>
> 理由：不支持 iframe 的录制器在真实业务系统上（尤其是老系统、嵌第三方组件的系统）基本废掉。但实现成本不高——`frameLocation` 差分算法在 `panel/js/background/recorder.js:271-293`，核心就 20 行。

### D9 · 要不要流程控制（if / while / forEach）？

> 推荐：**默认不要**。
>
> 一旦加了流程控制，你的"命令列表"就变成了一门**编程语言**，随之而来的是：作用域、嵌套、跳转、调试器、语法校验……复杂度上一个数量级。
>
> 如果确实需要循环，先用**数据驱动（CSV + 参数化）** 顶一阵子，成本低得多。

### D10 · 命令集要多大？

KR 有 **629 个 handler**（来自 153 个基础方法 × `assert/verify/store/waitFor/AndWait` 变体元编程）。

> 推荐：**从 12 条 P0 命令起步**（90 号 §阶段 1 已列出），跑通端到端后再按实际卡点扩。
>
> 关键是**保留元编程机制**（`doXxx` 自动派生 `assertXxx`/`verifyXxx`/`storeXxx`/`waitForXxx`/`xxxAndWait`），这样你写 1 个基础方法白送 5 个命令。这是 KR 最聪明的设计之一，见 TECH-03。

### D11 · 单人用还是团队用？

如果是团队用，你需要额外考虑（本套文档**没有**覆盖）：
- 用例的版本管理（存 Git？存共享盘？）
- 命名规范与用例组织
- 回放报告的汇总

> 推荐：**先按单人自用做**，团队协作用 Git 管 `.krecorder` 文件（它是文本格式，天然可 diff）。

### 4.2 Java 背景需要补的 Web 概念对照表

你说过只熟 Java，这几个概念是本套文档的前置知识，我用 Java 类比帮你过一遍：

| Web / 扩展概念 | Java 类比 | 差异要注意 |
|---|---|---|
| 事件冒泡 / 捕获（capture） | Servlet Filter 链的前置/后置 | 捕获阶段自上而下，冒泡自下而上；**KR 用捕获阶段抢在页面自身 handler 之前** |
| `addEventListener` | `addActionListener` / 观察者模式 | 无 |
| Content Script 的 ISOLATED world | 独立 ClassLoader 加载同一份类 | 同一个 DOM，两套 JS 堆，变量互不可见 |
| `chrome.runtime.sendMessage` | JMS Topic（广播） | 所有监听者都收到，靠 `sender.tab.id` 自己过滤 |
| `chrome.tabs.sendMessage` | JMS Queue（点对点） | 指定 tabId + frameId |
| `RemoteObjectHelper` RPC | RMI stub / 动态代理 `InvocationHandler` | 跨 world 调用，靠 `postMessage` 传序列化后的方法名+参数 |
| `retryUntilSuccess(fn, 60, 500)` | Spring Retry `@Retryable(maxAttempts=60, backoff=500ms)` | 无 |
| Service Worker 30 秒回收 | 无状态 Bean / Lambda 冷启动 | **不能存状态**，这是 D2 决策的根因 |
| `Promise` / `async-await` | `CompletableFuture` | 单线程事件循环，没有真并行 |
| `chrome.storage.local` | `Preferences` API / 本地 KV | 异步，回调或 Promise |
| 新式 formatter 契约 | `Function<TestCase, String>` | 纯函数，无副作用 |
| 旧式 formatter 层叠 | 模板方法 + 子类覆盖，但**用全局函数实现** | 没有 `@Override` 检查，覆盖了你都不知道 |
| `.krecorder` marshall/unmarshall | JAXB / Jackson 的 `writeValue` / `readValue` | 目标格式是 HTML 不是 XML/JSON |
| 命令元编程（doXxx 派生 5 个变体） | 运行时用反射 + 动态代理批量生成方法 | JS 里就是遍历原型链 + 字符串拼方法名 |
