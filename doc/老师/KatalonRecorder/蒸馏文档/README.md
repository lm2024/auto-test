## 三分钟速通：这个插件到底怎么回事

**一句话**：它是一个「把用户在浏览器里的 DOM 事件翻译成 Selenese 命令表、再把命令表逐条翻译回浏览器操作」的双向翻译器。

**最反直觉的一件事**（理解整个工程的总钥匙）：

> **它的后台大脑不在 Service Worker 里，而在一个用 `chrome.windows.create({type:"popup"})` 开出来的独立窗口里。**

证据：`worker_wrapper.js:1-26` 的 `importScripts` 清单里没有 `recorder.js`、没有 `window-controller.js`、没有 `playback/`；而 `panel/index.html:1001-1016` 把它们全部加载了。

原因：MV3 的 SW 空闲 30 秒被回收、没有 DOM、没有 `window.prompt()`，承载不了录制状态机。

**如果你只读一段话就走，请记住上面这段。** 带着「MV3 = SW 当后台」的假设去读代码，你会一路懵到底。

## 用户最初的三个疑问，答案在这里

> **Q：我正常用浏览器调试点击按钮会有好多访问请求，但它这里显示的就是我的事件？**
> A：它**根本没申请 `webRequest` 权限**，工作在 DOM 事件层不是 network 层。一次"点登录"在 network 层是 1 次 POST + 12 次静态资源 + 3 次埋点；在 DOM 事件层就是一个 `click`。→ `00` §5.1 / `TECH-01` §3.4

> **Q：它怎么知道是什么事件？**
> A：白名单（只监听有语义的事件）+ 入口守卫（`input` 不产命令、`change` 才产）+ 状态机（标志位防重复），三层收敛。→ `TECH-01` §4 含完整合并总表

> **Q：怎么调整顺序？日志旁边那些功能是什么？**
> A：命令表格是纯前端 DOM，用 jQuery UI `sortable` 拖拽，拖完重排编号。日志旁是五个标签页：Log / Screenshots / Variables / Reference / Self-healing。→ `TECH-04` §5、§8

## 三条最重要的警告

1. **🔴 `pandoraboz`**：MAIN↔ISOLATED 的 RPC 代理用明文硬编码密钥 + `postMessage(..., "*")` + 不校验 origin。同页任意第三方脚本都能拿到 `chrome.storage` 完整读写权。**复刻时必须换成随机 nonce + origin 校验。**

2. **🔴 别"修好" `default_popup`**：`manifest.json:44` 那行指向不存在的目录且写错了位置——**正因为它无效，`action.onClicked` 才会触发**。谁好心把它修正到 `action` 里，整个插件就点不开了。正确做法是**删掉这一行**。

3. **🔴 别把 DOM 当数据源**：原版用「双层 div 分别存 real 值和 show 值」来存命令数据，导致排序、撤销、导出各写一套读取逻辑。这是它最大的技术债，**必须改成单一 store**。

完整缺陷清单：`TECH-01` 附录（B1-B20）、`TECH-05` 附录（14 项）、`TECH-07` 附录（S 系列）、`90` §3（23 项必改写清单）。
