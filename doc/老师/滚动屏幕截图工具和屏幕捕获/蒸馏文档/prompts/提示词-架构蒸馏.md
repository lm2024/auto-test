# 提示词模板：架构蒸馏

> 用途：让一个 Agent 对任意 Chrome 扩展工程做完整逆向蒸馏，输出架构文档与模块清单。

## 提示词

```
你是一名资深浏览器扩展逆向工程师。请对以下 Chrome 扩展工程做完整的架构蒸馏，并输出一份中文《架构蒸馏文档》。

工程路径：{PROJECT_PATH}
扩展版本：{VERSION}
目标：理解它的一切，以便我筛选裁剪后改造成自己的个人插件。

请完成以下任务：

1. 读取 manifest.json，列出：
   - manifest_version、入口页面、service worker
   - permissions / optional_permissions / host_permissions
   - content_scripts（注入范围、run_at、all_frames）
   - web_accessible_resources
   - commands、oauth2、CSP

2. 建立文件清单与角色映射：每个 JS/HTML/CSS 文件一句话说明职责，标注是核心还是工具库。

3. 绘制进程模型图：
   - service worker / popup / content script / 独立窗口 / 标签页
   - 各进程之间的消息通道（runtime / tabs / connect / postMessage / WebSocket）

4. 梳理核心数据流（至少三条）：
   - 截图流：从点击到保存/上传
   - 录制流：从配置到分片输出
   - 认证流：cookie / OAuth / 用户信息

5. 列出所有服务端接口与域名（HTTP、WebSocket、第三方），标注硬编码位置。

6. 列出浏览器兼容策略：UA 检测、API 回退、页面限制、file 权限。

7. 输出改造建议：
   - 可整体删除的模块（品牌、会员、统计、跨扩展）
   - 建议保留并重写的模块
   - 必须注意的隐藏依赖

输出格式：Markdown，分章节，含 ASCII 架构图。不要修改任何源文件。
```

## 使用说明
- 把 `{PROJECT_PATH}` 替换为工程绝对路径
- 如果工程是 MV2，额外要求 Agent 标注 MV2 → MV3 迁移点
- 可追加要求：输出 `docs/` 目录，按模块拆分多份文档
