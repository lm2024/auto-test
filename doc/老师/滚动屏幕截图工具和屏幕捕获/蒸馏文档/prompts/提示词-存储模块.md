# 提示词模板：本地存储模块

> 用途：让 Agent 复刻 IndexedDB + FileSystem 的视频本地存储与视频管理页面。

## 提示词

```
请为一个 Chrome 扩展实现录制视频的本地存储与管理模块。输出可直接运行的代码。

## 功能需求

### 1. IndexedDB 封装
- 数据库名建议：your_ext_name，object store：recordings（autoIncrement）
- index：by_id（unique）
- 记录结构：
{
  "id": timestamp,
  "fileUrl": "filesystem:chrome-extension://.../persistent/xxx.webm",
  "detail": { "title", "size", "duration", "timeStamp", "thumbnailUrl", "recordType" }
}
- API：init / save / get / getAll / update / delete / deleteAll

### 2. FileSystem API 封装
- requestFileSystem(PERSISTENT, 50MB)
- save(blob, filename)：首片创建文件
- append(blob, filename)：追加分片（复用 FileWriter）
- remove(filename)
- do_save 返回 file.toURL()

### 3. 录制集成
- 本地录制时每 3s 一个分片：
  - 首片 fileSaver.save + DB.save
  - 后续片 fileSaver.append + DB.update 元数据（大小/时长）

### 4. 视频列表页
- 读取全部记录倒序展示（缩略图、标题、时长、大小）
- 点击进入详情
- 单条删除：先删文件再删 DB
- 全部删除：确认后遍历删文件 + deleteAll

### 5. 视频详情页
- video 加载 fileUrl
- canplay 后 canvas 截取缩略图保存并更新 DB
- 重命名：更新 detail.title
- 下载：
  - 申请 downloads 权限
  - 大文件用 EBML 修复（见下）
  - chrome.downloads.download({url, filename, saveAs:true})
  - 失败降级 <a download>
- 删除

### 6. WebM Seek 修复
- 使用 ts-ebml / EBML.js：
  - Reader + Decoder 解析
  - tools.makeMetadataSeekable(metadatas, duration, cues)
  - 重组 blob 使播放器可拖动进度条
- 文件超过 1.4GB 跳过修复

## 验收
- 录制边录边写不卡顿
- 浏览器重启列表仍在
- 下载视频可 seek
- 删除记录同步删除文件
- 存储满有错误处理
```

## 使用说明
- 可要求去掉 YouTube/Drive 分享
- 文件配额可根据需要调整
