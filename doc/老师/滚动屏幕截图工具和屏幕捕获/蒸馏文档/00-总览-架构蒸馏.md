# 00 总览：AwesomeScreenshot 2.0.5 架构蒸馏

## 1. 项目身份

- 扩展名：Scrolling screenshot tool & screen capture（AwesomeScreenshot）
- 版本：2.0.5
- 清单：`manifest_version: 3`
- 入口：`action.default_popup = popup2.html`，`background.service_worker = javascripts/bundles/serviceWorker.bundle.js`
- 前端：部分页面是 React bundle（`popup2.bundle.js`、`edit.bundle.js`、`annotate.bundle.js` 等），部分是原生 JS/jQuery（`popup.js`、`bg.js`、`record.js` 等）
- 录制内核：RecordRTC 5.5.9（`RecordRTC.js`）
- 标注内核：Diigo Image Annotator（`libs/diigo-image-annotator.min.js`）
- 截图内核：html2canvas + 自研滚动拼接算法（`content.bundle.js` 内）

## 3. 进程模型

```
┌────────────────────────────┐
│  Service Worker (MV3)       │  生命周期短、事件驱动
│  serviceWorker.bundle.js    │  默认选项、install、record 端口
└──────────┬─────────────────┘
           │ chrome.runtime / chrome.tabs / chrome.storage
┌──────────▼──────────────────────────┐
│  Popup (popup2.html)                 │  点击工具栏图标弹出
│  视图: main / capturing / preparing  │  screenshot 与 record 双 Tab
└──────────┬───────────────────────────┘
           │ runtime.sendMessage / tabs.sendMessage
┌──────────▼──────────────────────────┐
│  Content Script (content.bundle.js)  │  注入所有 http/https 页面
│  选区遮罩、滚动截图、快捷键、录制UI   │  all_frames: true
└──────────┬───────────────────────────┘
           │
┌──────────▼──────────────────────────┐
│  独立窗口/标签页                      │
│  capture-desktop.html 桌面截屏        │
│  camera.html 摄像头预览(PiP)          │
│  record.html 录制后台页               │
│  edit-react.html 图片编辑/标注        │
│  annotate-react.html 标注             │
│  video-list.html / video-react.html  │
└──────────────────────────────────────┘
```

关键点：MV3 下没有长驻 background page，`bg.js` 这类“全局对象”在 `popup.js` 里通过 `chrome.extension.getBackgroundPage()` 访问的写法是 MV2 遗留；新版 `popup2.js` 改用 `chrome.extension.getViews({windowId})` 找录制窗口。

## 4. 消息通道

| 通道 | 用途 |
| --- | --- |
| `chrome.runtime.sendMessage` | popup/service worker/录制页之间的全局消息 |
| `chrome.tabs.sendMessage(tabId, msg, {frameId:0})` | 向指定标签页 content script 发消息 |
| `chrome.runtime.connect({name:"record"})` | 录制长连接端口，断开即恢复状态 |
| `window.postMessage` | camera 预览窗口与后台交换流 |
| `chrome.runtime.onMessageExternal` | 跨扩展设置同步 |
| WebSocket | 云端视频分片上传 |

## 5. 核心数据流

### 5.1 截图流
1. popup 点击 Visible/Selected/Entire/Desktop → `chrome.runtime.sendMessage({action: ...})`
2. bg.js 收到后向当前标签页 `sendMessageToTab`
3. content script 绘制选区遮罩/执行滚动拼接
4. 数据以 `dataURL` / `blob` 回传 bg.js
5. bg.js 走 `image_upload.js` 上传队列（云端）或打开 `annotate-react.html`（本地）

### 5.2 录制流
1. popup 配置录制选项 → 打开 `record.html`（desktop 用 popup 窗口，camera 用普通标签）
2. `record-bg.js` 收到 `startRecord` → 注入 content script → `beginRecord`
3. `record.js` 获取麦克风流 + 视频流 → 混音 → RecordRTC 分片
4. 本地模式：分片写入 FileSystem（3s 切片）→ IndexedDB 记录
5. 云端模式：WebSocket 上行（500ms 切片）→ 服务端返回 videoURI

### 5.3 认证流
1. `chrome.cookies.getAll({url: baseURL})` 读取 `screenshot_personal_*` cookie
2. 有 `screenshot_personal_fullname` 即认为已登录
3. 调 `/api/v1/user/einfo` 拉取额度/权限
4. 写入 `chrome.storage.local.userinfo`

## 6. Manifest 权限策略

```json
{
  "permissions": ["storage", "unlimitedStorage", "desktopCapture", "activeTab", "scripting"],
  "optional_permissions": ["downloads"],
  "host_permissions": ["<all_urls>"],
  "content_scripts": [{
    "all_frames": true,
    "matches": ["http://*/*", "https://*/*"],
    "run_at": "document_end"
  }]
}
```

- `activeTab` 用于临时访问当前页
- `scripting` 用于动态注入录制相关脚本
- `desktopCapture` 用于桌面/窗口/系统音频捕获
- `downloads` 按需申请（保存文件/保存到子目录）
- `notifications` 也按需申请
- `host_permissions: <all_urls>` 是为了 content script 与截图

## 7. 浏览器兼容策略

1. `detect.js` 检测 Chrome/Edge/Firefox/Opera/Safari、Windows/Mac/Linux。
2. RecordRTC 内部按浏览器选择录制器：
   - Chrome 49+ 用 MediaRecorder（`MediaStreamRecorder`）
   - 老版本 Chrome/Opera 用 WhammyRecorder（canvas + WebP 帧合成 webm）
   - Safari/Firefox 用 MediaStreamRecorder
   - `MultiStreamsMixer` 处理多流混音
3. Edge 识别：`/Edg/.test(navigator.userAgent)`，统计与跳转都区分 Edge/Chrome。
4. 页面限制：`chrome://`、`edge://`、`chrome-extension://`、webstore、`about:blank` 不能注入 content script，相关按钮置灰。
5. `chrome.extension.isAllowedFileSchemeAccess()` 判断 file:// 权限。
6. 桌面录制失败按操作系统区分错误文案（Mac 系统权限 / Windows 音频源冲突）。

## 8. 改造为个人插件时的裁剪建议

### 可整体删除
- 所有 `awesomescreenshot.com` / `awesomescreenshot.cn` / `preview.diigo.com` 域名相关逻辑
- `googleOAuth.js`、`cors_upload.js`、`upload-video.js` 中的凭据
- `cga.js`、`insertGoogleAnalytics.js` 统计
- `extensionmessage.js` 跨扩展同步
- `in-place-play.js` 三方平台嵌入
- 会员/额度/升级弹窗逻辑

### 建议保留并重写为个人服务
- IndexedDB + FileSystem 本地存储
- 滚动截图拼接算法
- 选区截图 UI
- RecordRTC 录制流程
- WebSocket 分片协议（可换自己的服务端）
- 权限与页面限制处理

### 必须注意的隐藏依赖
- `manifest.json` 的 `key` 是 Chrome 商店固定 key，个人开发请删除
- `container: "GOOGLE_DRIVE"` 与 Google Drive 集成相关
- `update_url` 指向 Chrome 商店更新地址
- CSP sandbox 允许 `ws://localhost:8097` 是开发期 WebSocket，可保留用于本地调试
