# 09 隐晦知识点（逆向蒸馏发现的隐藏细节）

这份文档记录代码里不容易一眼看出来的知识点，是“蒸馏能力”中最有价值的部分。

## 1. Cookie 认证体系

- 登录态完全靠 `chrome.cookies.getAll({url: baseURL})` 读取：
  - `screenshot_personal_fullname`：是否登录
  - `screenshot_personal_type`：`"1"` 表示会员
  - `screenshot_personal_premium_level`：0/1/2 等级
  - `screenshot_personal_uid`：用户 ID
  - `screenshot_personal_permission`：权限串
- `refreshCookie()` 请求 `/promotion_ex` 刷新 cookie
- `refreshUserInfo()` 请求 `/api/v1/user/einfo` 同步额度到 `chrome.storage.local.userinfo`

## 3. Google OAuth 细节

- `manifest.oauth2.client_id`：`934696770472-c4k28j2t25p9fpntqsiblj12v8k8cob3.apps.googleusercontent.com`
- `googleOAuth.js` 硬编码了 `clientSecret`（`wrVV86YTdcrqYtct2BRapBpm`）和另一套 clientId
- 流程：
  1. 打开 `accounts.google.com/o/oauth2/v2/auth`（access_type=offline）
  2. 授权回调到 `https://www.awesomescreenshot.com/google_auth_extension`
  3. 监听 `chrome.tabs.onUpdated` 捕获 URL 中的 code
  4. 用 code 换 accessToken + refreshToken
  5. 存 `localStorage.google_oauth`
  6. 30 天后强制重新授权；accessToken 过期时用 refreshToken 刷新
- 安全提示：把 client secret 放进前端扩展本身就是泄露，个人项目应使用代理服务或 PKCE

## 5. CSP 与开发调试

```json
"content_security_policy": {
  "extension_pages": "script-src 'self' ; object-src 'self'",
  "sandbox": "sandbox allow-scripts; script-src 'self' https://ssl.google-analytics.com ... http://localhost:8097/; object-src 'self'; connect-src ws://localhost:8097"
}
```

- `localhost:8097` 是开发期 WebSocket，可本地联调
- GA / Facebook / Twitter 脚本被允许，说明有社交统计
- 注意 MV3 的 `script-src` 不能有远程 JS（扩展页），但 sandbox 页面可以

## 6. 额度与限制逻辑（免费→付费）

- 免费：100 张图片、20 个视频、5 分钟视频、720p
- 高级：1080p / 4K、无限量
- 逻辑点：
  - `showLimit()` / `showTry()` / `hideTip()` 控制 UI 提示
  - `checkTimeLength()` 在 301000ms（约 5 分钟）自动停止云端录制
  - 2 小时阈值弹 300x400 通知窗口（`twoHoursCount` 防止重复）
  - 云空间 75% 时显示“try”提示
- 升级按钮带 `data-reason` 埋点，例如 `upgrade from recording menu`

## 7. Badge 用法

- 倒计时：badge 显示剩余秒数
- 录制中：badge 显示录制时长
- 云端错误：badge 显示 `!`
- 新版公告：badge 显示 `New`，点击后打开博客并清除

## 8. FileSystem API 与 IndexedDB 的配合

- 录制分片写 `requestFileSystem(PERSISTENT, 50MB)`（`file.js`）
- 元数据写 IndexedDB（`DB.js`）
- `file.toURL()` 返回 `filesystem:chrome-extension://.../persistent/xxx.webm`
- 注意：IndexedDB 存的是 URL 不是 blob，删除时要同步删文件
- 大文件（>1.4GB）下载跳过 EBML 修复直接下载

## 9. WebM 流式文件问题

- 边录边写的 webm 缺少 metadata，播放器无法 seek
- `getSeekableBlob` 用 `ts-ebml`（EBML.js）解析并重建 metadata：
  - `EBML.Reader` 收集 metadatas / duration / cues
  - `EBML.tools.makeMetadataSeekable` 重新编码
- 这是很多录屏插件播放“卡住”的根因，蒸馏时务必保留

## 10. 混音与回授

- 录 Tab 声音时在后台页播放 `tabSoundAudioPlayer`，否则 tabCapture 的音频 track 不被消费会静音
- 混音用 `gainNode.gain.value = 0` 静音输出，防止录制端回授
- 麦克风热插拔：监听 `track.onended` → 重连 `default` 设备

## 11. 桌面录制音频的特殊性

- `chrome.desktopCapture.chooseDesktopMedia(["screen","audio","window"])`
- Windows 上系统音频常报 `Could not start audio source`，错误引导页专门处理
- 首次 Windows 桌面录制会弹“系统音频”提示（`alert-win` localStorage 只提示一次）

## 17. MV2 遗留痕迹

- `chrome.extension.getBackgroundPage()` 在 `popup.js` / `camera.js` 使用
- `chrome.browserAction` 在部分旧文件使用（新代码用 `chrome.action`）
- `bg.js` 的大量全局变量（`window.xxx`）是 MV2 常驻页的产物
- MV3 service worker 不常驻，`chrome.extension.getViews` 只在扩展页之间工作
- 蒸馏时建议把全局状态收敛成消息协议 + `chrome.storage`，这是最大重构点

## 18. 其它小细节

- `maxCaptureHeight = 100000`：整页截图超过 10 万像素高度限制
- `screenSize` 上报用 `screen.width * devicePixelRatio`（物理像素）
- `recordRatio` 用于 custom 录制保持宽高比
- `desktop_delay_sec` 与 `delay_sec` 分开存储，互不影响
- `save-as` 开启时申请 `downloads` 权限，关闭时仍用浏览器默认下载
- 卸载调查 URL、安装跳 setup、首次弹博客公告都是产品运营细节
- `chrome.storage.local` 的 `options` 是单对象，所有设置共用
