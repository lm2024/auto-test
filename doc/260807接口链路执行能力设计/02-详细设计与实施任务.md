# 接口链路执行能力改进 - 详细设计与实施任务

## 1. 公共业务组件和子流程

### 1.1 用户怎么用

在链路编辑页节点列表上方增加：

```text
新增节点 | 插入公共组件
```

组件列表只显示业务名称：

```text
登录-普通用户
登录-管理员
创建测试订单
清理测试订单
获取系统字典
```

用户选择组件并填写输入参数，不打开组件内部画布。

### 1.2 数据设计

公共组件复用现有链路表，增加：

```text
component_flag       是否公共组件
input_schema         输入参数定义 JSON
output_schema        输出参数定义 JSON
component_version    当前版本
```

示例：

```json
{
  "name": "登录-普通用户",
  "inputs": [{"name": "username", "required": true}],
  "outputs": [{"name": "token", "type": "string"}]
}
```

主链路保存组件引用节点：

```json
{
  "nodeType": "COMPONENT",
  "componentChainCode": "login_normal",
  "componentVersion": 3,
  "inputMapping": {"username": "{{loginUser}}"}
}
```

第一版执行时直接调用组件链路，不做物理展开；执行日志显示一个组件节点，点击后查看内部节点。

### 1.3 代码落点

| 文件 | 任务 |
|---|---|
| `TestChain` | 增加公共组件标识和输入输出字段 |
| `TestNodeConfig` | 增加组件引用字段或在 `nodeType` 中区分 |
| `ChainServiceImpl` | 新增公共组件列表和引用校验 |
| `ExecuteServiceImpl` | 执行组件节点并合并输出变量 |
| `ChainEdit.vue` | 增加“插入公共组件”入口 |
| `NodeConfigPanel.vue` | 组件输入参数映射 |

## 2. 环境、账号和测试数据

### 2.1 用户操作

链路编辑页顶部增加三个选择项：

```text
执行环境：测试环境
执行账号：普通用户-01
数据集：订单回归数据
```

用户不再修改每个节点的完整 URL。

节点 URL 统一保存为：

```text
{{baseUrl}}/api/order/create
```

### 2.2 数据优先级

```text
本次执行参数
> 数据池当前行
> 环境变量
> 链路默认变量
```

### 2.3 前置和后置

链路编辑页增加两个默认折叠区域：

```text
执行前准备：调用“创建测试用户”
执行后清理：调用“删除测试用户”
```

第一版只允许引用 HTTP 公共组件，不直接开放数据库 SQL，避免测试人员误删数据。

### 2.4 代码落点

| 模块 | 任务 |
|---|---|
| 环境管理 | 新增环境编码、名称、变量 JSON |
| 链路配置 | 保存默认环境、默认账号、默认数据池 |
| 执行请求 | 执行前解析环境和数据池变量 |
| 执行服务 | 前置组件成功后才执行主链路；后置组件使用 finally 执行 |
| 前端 | 链路顶部增加环境/账号/数据集选择器 |

## 3. 等待和轮询能力

### 3.1 不新增复杂画布节点

在 HTTP 节点的“高级配置”中增加：

```text
执行后等待业务完成：关闭 / 开启
查询接口：订单查询
判断字段：$.status
期望值：SUCCESS
最大等待：60 秒
间隔：3 秒
```

用户理解的是业务目标，系统内部实现轮询。

### 3.2 执行逻辑

```text
执行当前接口
-> 等待间隔
-> 调用查询接口
-> JSONPath 读取状态
-> 等于期望值：继续
-> 不等于：未超时则继续轮询
-> 超时：失败，显示最后响应
```

### 3.3 第一版范围

- 只支持 HTTP 查询接口
- 只支持 JSONPath + 等值判断
- 超时后保存最后一次请求和响应
- 不做任意条件跳转

## 4. 录制整理和用例生成

### 4.1 页面位置

流程改为：

```text
停止录制 -> 录制整理 -> 推送到平台
```

整理页仍位于插件，不放到后端链路编辑页。

### 4.2 请求分类

在 `recordedApis` 每条数据增加：

```json
{
  "captureCategory": "BUSINESS",
  "captureReason": "窗口内 POST 请求",
  "selected": true,
  "duplicateKey": "POST /api/order"
}
```

第一版使用规则，不依赖 AI：

```text
BUSINESS：窗口内 Fetch/XHR，非静态、非埋点、非 OPTIONS
POLLING：同 URL 短时间重复出现
NOISE：静态资源、埋点、心跳
DUPLICATE：方法、URL、请求体完全相同
UNKNOWN：无法判断，默认不选中
```

### 4.3 整理页操作

顶部按钮：

```text
选中业务接口 | 删除重复 | 仅看待确认 | 全部取消
```

每组请求显示：

```text
第 1 步：点击查询
POST /api/order/query       业务接口       已选中
GET  /api/track              埋点接口       已忽略
GET  /api/order/query        重复请求       已忽略
```

### 4.4 代码落点

| 文件 | 任务 |
|---|---|
| `plugin-test/background.js` | `saveApi()` 计算分类、重复键、默认选中状态 |
| `plugin-test/sidepanel.html` | `#apiList` 增加分类、原因和批量操作 |
| `plugin-test/sidepanel.js` | `render()` 展示整理页，`doPush()` 只提交 selected 请求 |
| 后端插件接口 | 接收节点名称、分类、忽略标记和 trace 分组 |

## 5. 画布节点和子流程

### 5.1 节点显示

每个节点增加：

```text
步骤编号
节点名称
请求方法
接口路径
变量提取标识
断言标识
```

100 个节点时，节点显示不能只依赖 URL；必须显示步骤号，方便从失败日志跳回画布。

### 5.2 子流程入口

链路编辑页左侧增加“分组”按钮：

```text
选择节点 -> 创建子流程
```

示例：

```text
主流程：登录 -> 下单 -> 支付 -> 查询
登录子流程：打开登录页 -> 获取验证码 -> 登录 -> 提取 Token
```

第一版允许把连续节点保存为子流程，不支持跨链路动态修改内部节点。

### 5.3 代码落点

| 文件 | 任务 |
|---|---|
| `frontend/src/graph/graph.js` | 新增蛇形布局和 DAG 折行布局 |
| `frontend/src/views/ChainEdit.vue` | 增加布局切换、范围提示、节点定位 |
| `frontend/src/components/x6/HttpNode.vue` | 增加步骤号和状态标记 |
| `ChainServiceImpl` | 保存子流程引用和版本 |

## 6. 失败分析

### 6.1 失败分类

执行详情页将失败分为：

```text
配置错误 / 环境错误 / 认证错误 / 请求错误 / 断言错误 / 数据错误 / 超时
```

### 6.2 用户看到的内容

```text
节点：查询订单
结果：断言失败
期望：$.status = SUCCESS
实际：$.status = PAYING
建议：等待订单状态完成后再查询
```

不是只显示“接口返回 200，但测试失败”。

### 6.3 代码落点

| 文件 | 任务 |
|---|---|
| `ExecuteServiceImpl` | 统一生成 failureType、expected、actual、suggestion |
| `TestNodeExecuteLog` | 增加失败分类和对比信息 |
| `ExecuteDetail.vue` | 按失败类型显示解释和处理建议 |
| AI 分析组件 | 只作为补充，不替代结构化失败信息 |

## 7. 接口变更影响分析

### 7.1 节点指纹

保存节点时生成：

```text
method + normalizedUrl + requestFieldNames + assertJsonPaths
```

节点变更时，与历史节点指纹比较。

### 7.2 用户提示

```text
接口 POST /order/create 已发生变化
影响 6 条链路：
订单创建回归、审批回归、支付回归……
```

第一版只提示，不自动修改其他链路。

## 8. 实施顺序

### 第一期：不改数据库

1. `graph.js` 蛇形布局和 DAG 折行布局
2. `ChainEdit.vue` 布局按钮、节点定位、步骤号
3. `App.vue` 菜单分组
4. 新增工作台步骤清单
5. 插件录制整理页
6. 执行详情失败分类展示

### 第二期：增加少量字段

1. 环境变量
2. 公共组件标识
3. 前置/后置组件引用
4. 节点指纹
5. 组件版本

### 第三期：执行能力

1. 等待/轮询配置
2. 失败节点继续执行
3. 文件上传和文件断言
4. 脚本扩展

MQ 和数据库直连不进入第一期，必须先拿真实项目确认使用频率。

## 9. 验收标准

### 画布

- 100 个线性节点不能单列显示。
- 1280px 画布默认约 5 列。
- 自动布局只改坐标，不改边和执行顺序。
- 点击节点列表可定位并居中节点。

### 新手流程

- 首次登录后能看到明确的第 1 步。
- 每一步只有一个主要操作按钮。
- 没有链路时不会直接进入空白执行页。

### 录制整理

- 录制 50 个请求后能分出业务、轮询、噪声、重复。
- 推送只包含用户选中的请求。
- 每条被忽略请求显示忽略原因。

### 复用和维护

- 登录组件可被两条链路引用。
- 同一链路可切换测试环境，不修改节点 URL。
- 可以配置执行前准备和执行后清理。
- 失败详情能区分断言失败、认证失败、环境失败和请求失败。
- 节点变更能显示受影响链路。

## 10. 明确不做

1. 不把所有能力都做成画布节点。
2. 不默认展示 MQ、数据库、脚本等高级功能。
3. 不用 AI 黑盒决定接口是否保留。
4. 不改变普通 HTTP 链路的使用方式。
