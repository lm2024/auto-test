# 接口链路执行能力改进 - 人工验收清单

1. 链路画布自适应蛇形布局。
2. DAG 分层折行布局。
3. 画布“蛇形布局 / DAG 布局 / 适应屏幕”操作。

## 2. 启动方式

### 2.1 前端

```bash
cd auto-test/frontend
npm run dev
```

默认访问：`http://localhost:9094/`

### 2.2 后端

按项目现有方式启动后端和数据库。需要有可登录账号，才能验证工作台、链路和执行页面。

### 2.3 插件

重新加载目录：

```text
auto-test/plugin-test
```

在 Chrome 扩展管理页打开开发者模式，点击“加载已解压的扩展程序”。

## 3. 工作台和菜单验收

### 3.1 工作台

1. 登录平台。
2. 访问 `/workbench`。
3. 确认首页显示“测试流程”。
4. 确认显示 6 个步骤：准备链路、录制/导入、整理编排、变量断言、执行冒烟、查看失败。
5. 点击“开始测试”，应跳转到测试链路页面。
6. 点击任意步骤卡片，应跳转到该步骤对应页面。

预期：新用户进入平台后先看到操作顺序，不直接面对空白链路或执行页面。

### 3.2 菜单

确认左侧一级菜单只有：

```text
工作台
测试资产
执行结果
系统管理
```

逐个展开：

- 测试资产：测试链路、测试账号、登录配置向导、数据池、插件下载
- 执行结果：执行记录、定时任务
- 系统管理：分类字典、系统注册表、调用关系图、系统设置，以及管理员功能

预期：原有页面仍可访问，但不再全部平铺在一级菜单中。

## 4. 画布布局验收

### 4.1 线性链路

准备一条节点数量较多的链路，建议至少 20 个节点；也可以通过导入接口或重复新增节点模拟。

1. 进入链路编辑页。
2. 点击“蛇形布局”。
3. 确认节点按照多列排列，而不是全部在一列。
4. 确认第一行从左到右，第二行方向反向，第三行再恢复正向。
5. 点击“保存画布”。
6. 刷新页面，确认布局仍然保留。

预期：

- 1280px 左右宽度下通常显示约 5 列。
- 节点编号/顺序仍然连续。
- 连线存在，节点没有全部挤在同一条竖线上。

### 4.2 100 个节点

准备 100 个线性节点：

1. 点击“蛇形布局”。
2. 确认画布不是 100 行单列。
3. 缩放浏览器窗口宽度，再次点击“蛇形布局”。
4. 确认列数会根据画布宽度变化。
5. 点击“适应屏幕”，确认画布整体进入可视范围。

预期：节点数量增加只增加行数，不形成不可操作的超长单列。

### 4.3 DAG 链路

准备有分支的链路：一个节点连接两个节点，再汇聚到下一个节点。

1. 点击“DAG 布局”。
2. 确认分支节点仍按层级排列。
3. 确认同一层节点会在可用宽度内折行。
4. 点击“预览执行顺序”。
5. 确认预览层级与布局前一致。

预期：布局变化不能改变执行层级和边关系。

## 5. 录制整理验收

### 5.1 基本分类

1. 打开插件面板。
2. 点击“开始录制”。
3. 在被测页面完成一次真实操作。
4. 点击“停止录制”。
5. 查看录制列表中的接口元信息。

预期：新捕获请求会显示分类标识，例如：

```text
BUSINESS   业务请求
POLLING    轮询请求
NOISE      噪声请求
DUPLICATE  重复请求
```

### 5.2 批量选择

1. 点击“选中业务接口”。
2. 确认业务请求被勾选。
3. 确认噪声、轮询、重复请求默认未勾选。
4. 手工取消一个业务请求。
5. 点击“推送至平台”。

预期：推送内容只包含当前勾选的接口。

### 5.3 选择状态保持

1. 勾选或取消多个接口。
2. 使用搜索框或方法筛选。
3. 返回全部列表。

预期：之前的勾选状态不应因为重新渲染丢失。

## 6. 执行详情验收

### 6.1 失败分类

准备一个会失败的节点，例如：

- 请求一个不存在的 URL
- 使用错误账号触发 401
- 配置一个不匹配的断言
- 配置很短的超时时间

执行后进入详情页，确认失败节点旁显示分类标签：

```text
认证失败
环境/请求失败
断言失败
超时
变量配置失败
服务端错误
请求失败
```

点击“查看详情”，确认弹窗中有“失败分类”。

### 6.2 HTTPS WebSocket

在 HTTPS 反向代理环境访问执行详情页：

1. 打开浏览器开发者工具 Network。
2. 执行一条链路。
3. 查看 WebSocket 请求协议。

预期：HTTPS 页面使用 `wss://`，HTTP 页面使用 `ws://`。
