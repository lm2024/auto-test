# 接口自动化测试平台需求规格说明书（最终落地版）
## 一、项目概述
### 1.1 项目背景
公司纯内网环境下，业务接口测试长期存在配置效率低、人工摘抄易出错、新人上手门槛高、失败排查耗时长的痛点：
1.  测试人员需手动从浏览器抓包摘抄接口信息，逐个填写到测试工具中，重复工作量大；
2.  全链路接口参数依赖关系需人工梳理，易出现上下游参数不匹配导致执行失败；
3.  测试数据构造依赖人工编写，ID类递增参数、业务合规数据生成成本高；
4.  接口执行失败后，需人工比对请求响应、定位根因，排查效率低。

为解决以上问题，建设一套**轻量化内网接口自动化测试平台+自研浏览器录制插件**，形成「页面操作录制→自动识别参数依赖→一键生成测试流程→智能生成测试数据→自动化执行→AI排障」的完整闭环，大幅降低测试门槛、提升全流程效率。

### 1.2 建设目标
1.  **零额外中间件落地**：严格基于现有技术栈，不引入Redis、MQ、专业流程引擎，单实例即可部署，完全适配纯内网离线环境。
2.  **录制式零配置建用例**：通过浏览器插件录制页面操作，自动捕获接口、识别上下游参数依赖，一键生成完整测试链路，替代人工摘抄。
3.  **模板化测试数据生成**：基于已有链路配置模板，智能生成合规测试数据，支持ID自增/自定义策略，解决数据构造痛点。
4.  **可视化低门槛编排**：拖拽式画布完成流程调整，节点参数支持JSON格式化编辑、一键复制，普通测试人员无需编码即可上手。
5.  **精准AI赋能**：保留全链路测试数据生成、执行失败智能分析两个高价值AI能力，不做冗余功能。
6.  **全链路状态可视化**：执行过程实时回传状态，节点悬停看摘要、点击看详情、失败一键AI分析，执行过程全透明。

### 1.3 完整业务闭环
```
安装插件 → 开启录制 → 操作业务页面（点击/提交/跳转）→ 插件自动捕获接口 + 持久化存储 → 人工筛选有效接口 → 自动识别上下游参数依赖 → 一键推送至平台 → 自动生成测试链路 + 节点 + 参数关联规则 → 画布调整流程 → AI基于链路模板生成测试数据 → 触发执行 → 实时查看节点状态 → 失败节点一键AI分析 → 生成执行日志
```

### 1.4 三大交付模块
| 模块 | 技术栈 | 核心职责 |
|------|--------|----------|
| 后端服务 | JDK 8 + Spring Boot 2.7.7 + MySQL 5.7 + LangChain4j 0.35.0 | 链路管理、节点配置、自研执行引擎、日志存储、AI能力、插件对接接口、WebSocket推送 |
| 前端可视化平台 | Vue 3 + Vite + Element Plus + LogicFlow | 可视化流程编排、执行状态展示、节点详情编辑、日志查询、AI功能交互 |
| 浏览器插件 | Manifest V3 + 原生HTML/CSS/JavaScript | 页面接口录制、跨页面数据持久化、接口筛选、参数依赖识别、数据导出/一键推送平台 |

## 二、硬性技术约束（不可突破）
所有开发必须严格遵循，不得引入超出范围的依赖：
1.  **后端约束**
    - JDK 版本：必须兼容 JDK 8，不得使用 JDK 9+ 语法与API；
    - 框架：Spring Boot 2.7.7 固定版本；
    - 数据库：仅使用 MySQL 5.7，复杂JSON数据用 TEXT/LONGTEXT 字段存储，Java 层做序列化解析；
    - 中间件：禁止引入 Redis、MQ、专业流程编排引擎（LiteFlow/Activity等），异步、状态推送全部基于 Spring 原生能力实现；
    - AI组件：仅使用 LangChain4j 0.35.0（最后一个兼容 JDK 8 的稳定版本），对接内网兼容 OpenAI 协议的大模型服务。
2.  **前端约束**
    - 框架：Vue 3，构建工具兼容 Node.js 14.18.0 及以上版本；
    - 流程画布：使用 LogicFlow 开源组件，不得引入重型BPMN引擎；
    - UI 组件：Element Plus，保持企业级统一风格。
3.  **插件约束**
    - 规范：Chrome/Edge Chromium 内核，采用 Manifest V3 标准开发；
    - 网络：纯内网运行，无任何外网请求、无第三方SDK、无自动更新；
    - 权限：仅授权指定内网业务域名的请求捕获权限，范围可控。
4.  **环境约束**
    - 全程运行于公司内网，所有数据存储在内网服务器，不得出网；
    - 支持离线部署，所有依赖均为本地可安装包，无需外网下载。

## 三、后端服务功能需求
### 3.1 测试链路管理模块
测试链路为平台顶层业务单元，一条链路对应一个完整测试流程，所有节点配置作为链路模板存储于数据库。
1.  **基础CRUD**
    - 支持新增、编辑、删除、分页查询测试链路；
    - 核心字段：链路ID（自增主键）、链路编码（唯一）、链路名称、执行模式、链路描述、创建时间、更新时间；
    - 删除链路时同步删除关联的所有节点配置，历史执行日志保留。
2.  **执行模式配置**
    - 全串行模式：所有节点按排序顺序依次执行，前序节点失败则终止链路；
    - 分组并行模式：按并行分组标识划分节点组，组与组串行、同组内节点并行执行，单组失败则终止后续组执行。
3.  **链路复制与版本**
    - 支持基于已有链路一键复制生成新链路（编码自动加后缀），同步复制所有节点配置与参数规则；
    - 复制时链路ID自动生成新值，与原链路隔离，支持修改后快速生成新用例。
4.  **插件新建链路**
    - 接收浏览器插件推送的接口数据，自动创建全新测试链路+对应节点；
    - 新建链路默认执行模式为「全串行」，节点顺序与录制顺序一致；
    - 自动识别上下游接口的参数依赖关系，生成变量提取规则与占位符引用。

### 3.2 测试节点配置模块
节点为链路最小执行单元，对应一次HTTP接口请求，所有节点配置构成链路测试模板，存储于数据库。
1.  **节点基础配置**
    - 核心字段：所属链路编码、节点ID、节点编码（唯一）、节点名称、节点类型（本期仅HTTP类型）、排序号、并行分组标识；
    - 请求配置：请求URL、请求方法（GET/POST/PUT/DELETE）、请求头（JSON格式）、请求体类型、请求体内容；
    - 规则配置：变量提取规则（JSONPath格式，从响应提取变量存入上下文）、断言规则（校验响应是否通过）、变量占位符映射关系。
2.  **排序与分组规则**
    - 排序号为数字，数字越小执行优先级越高，同链路内排序号唯一；
    - 并行分组为空的节点按排序号串行执行；同分组标识的节点并行执行，组整体按组内最小排序号参与全链路串行排序。
3.  **批量节点导入**
    - 支持接收插件推送的批量接口数据，自动生成节点配置；
    - 支持解析上传的JSON文件，批量生成节点配置；
    - 导入时自动生成节点编码、按录制顺序赋值排序号、并行分组默认为空。
4.  **单节点编辑**
    - 支持修改单个节点的所有配置项，修改后实时更新数据库模板；
    - 支持单个节点的请求头、请求体JSON格式化校验，保障格式合法性。

### 3.3 自研流程执行引擎模块
平台核心模块，替代专业流程引擎，覆盖90%以上接口测试场景。
1.  **链路解析**
    - 接收执行请求后，根据链路编码查询所有关联节点配置（从数据库读取模板）；
    - 按排序号、并行分组标识做拓扑排序，生成执行计划；
    - 校验链路合法性：禁止循环依赖、禁止孤立节点、禁止分组嵌套。
2.  **异步执行机制**
    - 前端触发执行后，主线程立即创建执行记录、返回执行ID，任务提交至自定义线程池后台异步执行，不阻塞HTTP请求；
    - 线程池配置：核心线程数=CPU核数×2，最大线程数=CPU核数×4，有界队列（长度200），拒绝策略为调用方运行，防止OOM。
3.  **执行上下文管理**
    - 单次执行对应一个独立上下文，存储：执行ID、链路编码、全局变量Map（线程安全并发容器）、节点执行日志列表；
    - 变量占位符替换：节点配置中 `${变量名}` 格式的内容，执行前自动替换为上下文内的真实值，实现链路内参数传递；
    - 并行场景下变量读写保障线程安全，避免数据错乱。
4.  **单节点执行流程**
    1.  读取节点配置模板，替换变量占位符；
    2.  发起HTTP请求，记录请求参数、发起时间；
    3.  接收响应，记录响应码、响应体、耗时；
    4.  按提取规则从响应提取变量，更新至执行上下文；
    5.  按断言规则校验响应，判定节点执行状态（成功/失败）；
    6.  记录节点日志，通过WebSocket推送状态至前端。
5.  **异常中断规则**
    - 串行模式：单个节点失败，终止整条链路，后续节点标记为「跳过」；
    - 并行模式：同组内任意节点失败，标记本组失败，终止后续所有组执行；
    - 全链路异常捕获，单个节点失败不影响其他执行链路，不导致服务崩溃。

### 3.4 AI智能服务模块
本期仅保留2个核心功能，**所有AI能力均基于已有链路配置模板生成，无模板不凭空生成**。
#### 3.4.1 全链路测试数据生成
1.  **功能定位**：基于数据库中已有的链路节点配置模板，为整条链路生成符合业务规则的测试数据，回填至节点配置中。
2.  **触发前提**：必须存在已配置好的链路模板（节点URL、字段结构、参数位置已明确），从数据库读取模板后生成数据，无模板无法触发。
3.  **输入数据**：从数据库查询该链路所有节点的配置信息，包含：节点编码、请求方法、URL、请求头结构、请求体字段结构、字段业务含义。
4.  **ID生成策略（核心规则）**
    - 支持两种模式，可在触发时选择：
      1.  **自增模式**：基于链路历史执行过的最大ID值，按指定步长递增生成；步长支持自定义，默认步长为1，支持1-20范围内的跨度调整；生成时校验ID唯一性，避免冲突。
      2.  **自定义模式**：测试人员手动指定起始ID值，基于该值按步长生成后续ID。
    - ID类字段自动识别：请求体、URL路径中的主键ID、业务单号等字段，自动匹配生成规则。
5.  **通用数据生成规则**
    - 字段类型匹配：数字、字符串、日期、手机号、邮箱、身份证号等格式合法合规；
    - 业务逻辑合规：金额为正、状态值符合枚举范围、账号符合命名规则；
    - 上下游参数一致性：链路中依赖传递的变量，生成时保持前后节点值一致；
    - 默认生成正向可用测试数据，兼顾边界值场景。
6.  **输出与落库**
    - 按节点维度返回生成的请求头、请求体JSON数据；
    - 支持两种保存方式：① 临时回填到前端配置，人工确认后保存；② 直接更新数据库中的链路节点模板。

#### 3.4.2 执行失败智能分析
1.  **功能说明**：节点执行失败时，传入完整请求、响应、报错信息，自动分析根因并给出修复建议。
2.  **输入信息**：请求完整信息（URL、方法、请求头、请求体）、响应状态码、响应内容、错误堆栈信息。
3.  **分析维度**：参数格式错误、必填字段缺失、环境不可达、权限不足、业务校验失败、服务端代码异常、依赖数据不存在。
4.  **输出结果**：结构化返回3个字段：根因定位、排查步骤、修复方案。

### 3.5 浏览器插件专属对接接口
专门为插件提供的内网接口，支持跨域调用，全程数据内网流转。
1.  **接口1：插件推送接口→新建测试链路（核心）**
    - 路径：`POST /api/plugin/chain/create`
    - 入参：链路名称、接口列表数组（含完整请求头、请求体、响应数据）；
    - 核心处理逻辑：
      1.  校验参数合法性；
      2.  创建测试链路基础信息，生成唯一链路编码；
      3.  **自动识别参数依赖**：按录制顺序遍历接口，比对前序接口响应字段与后序接口入参字段，匹配字段名/语义一致的参数，自动生成变量提取规则与占位符引用；
      4.  批量写入节点配置表，按录制顺序赋值排序号；
      5.  返回新建成功的链路ID、编码、节点列表与参数关联关系。
2.  **接口2：插件推送接口→追加至现有链路**
    - 路径：`POST /api/plugin/chain/append`
    - 入参：目标链路编码、接口列表数组；
    - 处理逻辑：校验链路存在→追加节点（排序号顺延）→补充参数依赖规则→返回更新后的节点列表。
3.  **接口3：获取平台基础配置**
    - 路径：`GET /api/plugin/config`
    - 出参：支持的请求方法枚举、节点类型、默认配置项，用于插件与平台数据对齐。

### 3.6 执行日志管理模块
1.  **执行主日志**
    - 记录单次链路执行的整体信息，字段：执行ID、关联链路编码、执行状态（运行中/成功/失败）、开始时间、结束时间、总耗时、全局错误信息；
    - 支持按链路、执行状态、时间范围分页查询。
2.  **节点明细日志**
    - 记录单次执行中每个节点的完整详情，字段：关联执行ID、节点编码、执行状态、请求URL、请求头、请求体、响应码、响应头、响应体、执行耗时、错误信息；
    - 支持按执行ID查询全量节点日志，完整复现执行现场。
3.  **落库机制**
    - 节点执行日志先暂存于执行上下文内存；
    - 整条链路执行结束后，批量写入数据库，减少数据库IO开销。

### 3.7 WebSocket实时推送模块
1.  **连接管理**：前端进入执行页面时建立连接，绑定执行ID；连接断开自动清理会话；
2.  **推送时机**：节点开始执行、节点执行完成、整条链路执行结束；
3.  **推送内容**：节点编码、执行状态、耗时、响应码、简要错误信息；
4.  **实现方式**：会话存储于服务本地内存，执行线程直接推送，无中间件中转。

## 四、前端可视化平台功能需求
### 4.1 整体交互规范
- 采用企业级后台管理风格，左侧导航、右侧内容区布局；
- 所有操作有即时反馈，加载状态、成功/失败提示清晰；
- 画布操作符合通用交互直觉，支持快捷键、右键菜单。

### 4.2 导航菜单
1.  测试链路管理
2.  执行记录查询
3.  系统设置（大模型配置、线程池参数、ID生成默认规则）

### 4.3 测试链路管理页
1.  **列表区**：表格展示所有链路，列：链路编码、链路名称、执行模式、节点数量、创建时间、操作列；
2.  **筛选区**：支持按链路名称、编码、执行模式模糊搜索；
3.  **操作列**：节点编排、立即执行、复制、编辑、删除；
4.  **新增/编辑弹窗**：表单填写链路基础信息，提交后保存。

### 4.4 可视化流程编排页（核心页面）
采用**左-中-右三栏标准布局**。
#### 4.4.1 左侧：节点库
- 分类展示可拖拽节点，本期仅展示「HTTP请求节点」；
- 支持拖拽节点至画布，自动生成节点实例；
- 顶部增加「批量导入接口」按钮，支持上传JSON文件导入节点。

#### 4.4.2 中间：流程画布区
基于 LogicFlow 实现，核心能力：
1.  **画布基础能力**：无限画布、拖拽平移、滚轮缩放、网格对齐、右下角小地图、撤销/重做、一键自动布局、清空画布；
2.  **节点渲染**：卡片式节点，展示节点名称、请求方法、简要URL；
3.  **连线规则**：拖拽节点锚点建立连线，箭头指示执行方向，支持删除连线；
4.  **状态渲染**：执行时节点实时更新状态样式：
    - 待执行：灰色边框；
    - 运行中：蓝色边框+呼吸动画；
    - 成功：绿色边框+成功图标；
    - 失败：红色边框+失败图标；
5.  **顶部工具栏**：保存、撤销、重做、缩放控制、自动布局、AI生成测试数据、执行按钮。

#### 4.4.3 右侧：属性配置面板
- 未选中节点时展示提示文案，选中节点后展开配置表单；
- 分Tab展示：基础信息、请求配置、提取规则、断言规则；
- JSON格式配置项支持语法高亮、格式化校验、一键美化；
- 修改配置实时同步至画布节点，保存后更新数据库模板。

#### 4.4.4 节点详情与编辑弹窗（核心交互，必须满足）
点击任意节点弹出详情弹窗，支持查看、编辑、格式化、复制全能力：
1.  **基础信息区**：节点名称、执行状态（执行中展示）、耗时、起止时间；
2.  **请求配置区**
    - 展示完整URL、请求方法、请求头、请求体；
    - JSON类型内容支持**一键格式化/美化**、折叠展开、语法高亮；
    - 支持**一键复制**请求头、请求体、完整CURL命令；
    - 支持直接编辑修改，编辑后可保存更新节点配置模板；
3.  **响应详情区**：响应码、响应头、响应体，支持JSON格式化、一键复制；
4.  **错误信息区**：执行失败时展示完整错误堆栈；
5.  **AI功能入口**：失败节点底部提供「AI分析失败原因」按钮，点击后加载并展示根因、排查步骤、修复方案。

### 4.5 执行记录页
1.  **列表区**：分页展示所有执行记录，列：执行ID、关联链路、执行状态、开始时间、总耗时、操作列；
2.  **筛选区**：按链路、状态、时间范围筛选；
3.  **详情入口**：点击「查看详情」跳转至执行画布页，还原本次执行的节点状态与完整日志。

### 4.6 AI功能交互
1.  **全链路测试数据生成**
    - 入口：编排页工具栏「AI生成测试数据」按钮；
    - 前置校验：校验链路是否存在节点配置，无模板则提示无法生成；
    - 交互：点击后弹出配置弹窗，可选择ID生成模式（自增/自定义）、设置步长；确认后按钮置灰加载，生成完成后自动回填所有节点的请求头、请求体，弹出成功提示；
    - 支持人工确认后再保存到数据库模板。
2.  **失败原因分析**
    - 入口：节点详情弹窗内的分析按钮；
    - 交互：点击后按钮加载，结果以结构化卡片展示，支持复制内容。

## 五、浏览器插件功能需求
### 5.1 插件基础说明
- 适配浏览器：Chrome、Edge（Chromium内核，版本≥88）；
- 运行规范：Manifest V3，仅授权指定内网业务域名权限；
- 离线运行：无外网请求、无第三方依赖、数据仅存浏览器本地；
- 核心目标：替代人工抓包摘抄，录制页面操作触发的接口，一键生成测试链路。

### 5.2 核心功能模块
#### 5.2.1 录制控制模块（解决页面跳转/刷新数据丢失问题）
1.  **启停控制**：插件弹窗顶部展示「开始录制/停止录制」按钮，录制中插件图标高亮、实时显示录制时长；
2.  **跨页面持久化录制（硬性要求）**
    - 开启录制后，页面刷新、域名内跳转、同域名新开标签页，录制数据均不丢失；
    - 数据实时持久化至浏览器 `localStorage`，仅手动点击「清空记录」或停止录制后主动清除才会删除；
    - 页面重新加载后自动读取本地缓存的录制数据，无缝继续录制；
3.  **清空记录**：一键清空当前所有捕获的接口数据，同步清除本地缓存。

#### 5.2.2 接口列表展示模块
1.  **时序展示**：捕获的接口严格按录制时间顺序追加至列表，最新操作触发的接口在底部，顺序与业务操作顺序完全一致；
2.  **列表字段**：序号、请求方法标签（颜色区分）、URL路径、响应状态码、请求耗时；
3.  **类型自动标记**：自动区分业务接口、静态资源（js/css/图片）、埋点上报，默认隐藏静态资源与埋点，可通过筛选开关展示；
4.  **列表操作**：单条删除、勾选复选框、拖拽调整顺序。

#### 5.2.3 筛选与搜索模块
1.  **关键词搜索**：输入URL关键词，实时过滤列表；
2.  **方法筛选**：按GET/POST/PUT/DELETE筛选；
3.  **状态码筛选**：按成功/失败筛选；
4.  **自动过滤开关**：开启后自动隐藏静态资源、图片、埋点类无用请求。

#### 5.2.4 接口详情模块
点击列表任意接口，展开详情区域，展示完整原始数据：
1.  基础信息：完整URL、请求方法、请求时间、耗时、响应码；
2.  请求区域：请求头、请求体（支持JSON格式化查看）；
3.  响应区域：响应头、响应体（支持JSON格式化查看）；
4.  支持一键复制完整请求/响应内容。

#### 5.2.5 数据导出与推送模块（核心联动能力）
勾选目标接口后，提供两种导出方式，导出数据严格保留录制顺序、完整入参出参。
1.  **一键推送至测试平台**
    - 前置配置：插件设置页填写内网测试平台地址；
    - 支持选择「新建链路」或「追加到现有链路」；
    - 推送时携带完整的请求、响应原始数据，供平台识别参数依赖；
    - 推送成功后返回链路编码，弹窗提示跳转平台查看；
    - 推送失败展示具体错误原因，支持重试。
2.  **导出JSON文件**
    - 将勾选的接口按标准格式生成本地JSON文件，自动下载；
    - 文件包含完整的请求、响应数据与顺序信息，可上传至测试平台批量导入节点。

#### 5.2.6 基础编辑模块
- 支持修改单条接口的节点名称，导入平台后自动同步；
- 支持拖拽调整列表顺序，导入后的节点执行顺序与列表顺序一致。

#### 5.2.7 设置模块
- 测试平台内网地址配置；
- 自动过滤规则配置（配置忽略的URL关键词、域名）；
- 录制历史缓存开关；
- ID生成默认规则配置。

### 5.3 页面结构
1.  **Popup弹窗（主界面）**：点击浏览器右上角插件图标打开，尺寸380px×560px，包含录制控制、筛选栏、接口列表、操作按钮；
2.  **详情侧边栏**：点击接口详情时，弹窗右侧展开详情面板；
3.  **设置页**：独立页面，点击设置图标打开，配置全局参数。

### 5.4 捕获技术要求
- 劫持页面 `window.fetch` 与 `XMLHttpRequest`，覆盖前端99%的接口请求；
- 完整捕获请求URL、方法、请求头、请求体、响应头、响应体、耗时；
- 不侵入业务系统代码，纯旁路监听，不影响业务系统正常运行；
- 文件上传类二进制请求体，标记为「二进制数据」，不做格式化，保留原始结构。

## 六、核心业务规则与数据规范
### 6.1 参数传递与依赖识别规则
1.  **默认规则**：按录制时序，前序接口的响应字段与后序接口的入参字段，若字段名完全一致、或语义高度匹配（如`orderId`与`order_id`），自动识别为参数依赖；
2.  **实现方式**：平台接收插件数据后，自动为前序节点生成变量提取规则，为后序节点对应字段替换为变量占位符；
3.  **人工修正**：自动识别的依赖关系支持测试人员在编排页面手动修改、新增、删除，满足固定值传参、特殊状态值传参等场景；
4.  **执行校验**：链路执行前校验占位符是否存在对应变量，缺失则给出提示，避免执行时报错。

### 6.2 ID生成业务规则
1.  **自增模式**
    - 取该链路历史执行记录中同类型ID的最大值为基准；
    - 按设置的步长递增生成，步长默认1，支持1-20范围内自定义；
    - 生成后校验ID唯一性，避免与历史数据冲突。
2.  **自定义模式**
    - 测试人员输入起始ID值，系统基于该值按步长生成整条链路的ID序列；
    - 支持指定ID前缀、后缀、固定格式。
3.  **适用范围**：业务主键ID、订单号、单据编号等递增类字段，自动识别匹配。

### 6.3 插件与平台统一数据格式
插件推送、文件导入均采用以下JSON结构，两端严格对齐，字段直接映射数据库表：
```json
{
  "chainName": "测试流程名称",
  "chainCode": "可选，追加时必填",
  "interfaceList": [
    {
      "nodeName": "节点名称",
      "method": "POST",
      "url": "http://内网IP/api/xxx",
      "headers": "{\"Content-Type\":\"application/json\"}",
      "bodyData": "{\"id\":123,\"name\":\"test\"}",
      "responseData": "{\"code\":200,\"data\":{\"id\":123}}",
      "sort": 1,
      "parallelGroup": ""
    }
  ]
}
```

## 七、非功能需求
### 7.1 兼容性
- 后端：100%兼容JDK 8运行环境；
- 数据库：兼容MySQL 5.7，无高版本SQL语法；
- 前端：兼容Chrome、Edge主流版本，适配1920×1080及以上分辨率；
- 插件：兼容Chrome 88+、Edge 88+ 版本。

### 7.2 性能
- 单实例支持同时执行20条以上链路，单链路支持50个以内节点正常运行；
- 平台自身执行额外开销≤50ms/节点；
- 画布100个节点以内操作流畅无卡顿；
- 大模型调用超时默认120秒，超时自动中断；
- 插件录制支持单次捕获200条以内接口，列表滚动流畅。

### 7.3 稳定性
- 线程池有界队列+拒绝策略，防止批量执行导致服务宕机；
- 全链路异常捕获，单节点/单链路失败不影响整体服务；
- WebSocket断开支持前端自动重连，重连后拉取最新状态对齐；
- 插件本地缓存异常时自动降级，不影响业务系统正常使用。

### 7.4 内网安全
- 所有数据存储在内网MySQL，无任何外网数据传输；
- 插件仅授权指定业务域名权限，无越权访问；
- 敏感字段（密码、Token）支持配置脱敏展示，避免明文泄露。

### 7.5 易用性
- 录制→导入→执行全流程无需编码，普通测试人员30分钟内可上手；
- 节点参数编辑自带JSON格式化、校验，减少格式错误；
- 执行状态视觉区分明显，失败节点一键定位、一键分析。

| 序号 | 不足点描述 | 风险等级 | 修正方案 |
|------|------------|----------|----------|
| 1 | 自动参数依赖识别无法100%准确，语义相近但字段名不一致的参数可能漏识别 | 低 | 1. 优先按字段名精确匹配；2. 导入后在画布上高亮标记自动识别的依赖关系，测试人员可一键校验、手动补充；3. 执行前做参数缺失校验，提前报错 |
| 2 | ID自增模式下，若多人同时生成数据，可能出现ID冲突 | 低 | 1. 生成时加分布式数据库行级锁，保证同链路ID生成串行；2. 生成后立即校验唯一性，冲突则自动顺延步长重新生成 |
| 3 | 插件录制页面跳转时，极端场景下可能丢失跳转瞬间的请求 | 低 | 1. 采用 `webRequest` 浏览器API + 页面劫持双重捕获机制，兜底保障；2. 丢失的请求可通过二次录制追加，不影响核心流程 |
| 4 | 大模型生成数据格式可能存在偏差，无法直接回填 | 中 | 1. Prompt中强约束输出JSON格式，增加格式校验；2. 生成后后端做格式校验，失败自动重试1次；3. 前端提供人工编辑确认环节，不强制自动落库 |
