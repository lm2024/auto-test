# 架构设计：链路编排重构 + 单节点调试 + 全局变量 + 内外网识别 + 系统调用关系图

> 配套需求：`doc/260804前端框架登陆插件大变更/需求.md`
> 设计目标：**简洁、易操作、易理解**；测试人员手动新增/修改链路时能轻松拿到上一步返回值喂给当前节点；新增「系统调用关系图」菜单；表结构可重构，改完必须能编译打包启动；后端 Java 8 语法。

## 2. 技术栈选型

| 用途 | 选型 | 理由 | 是否新增依赖 |
|---|---|---|---|
| 链路编排画布 | **AntV X6 3.x** (`@antv/x6@^3.1.7` + `@antv/x6-vue-shape@^3.0.2`) | 节点即 Vue SFC，可直接复用项目已有 TDesign 组件渲染富节点；官方定位 DAG 引擎；插件生态完备 | **是** |
| 编排画布插件 | `@antv/x6-plugin-{selection,snapline,minimap,history,keyboard,clipboard}` | 框选/对齐线/小地图/撤销重做/快捷键/复制粘贴，开箱即用 | **是**（须锁 `3.0.0`） |
| 拓扑排序/环检测 | **@antv/algorithm** | 执行顺序由图拓扑决定，需拓扑排序；连线成环时前端即时报错 | **是** |
| 系统调用关系图 | **AntV G6** (v5) | 图可视化/分析引擎，原生支持力导/dagre/圆形/辐射布局、图算法；最适合「系统A→系统B」自动布局网络图 | **是** |
| 统计图表 | **ECharts 5.6** | 饼图/柱状图展示「按模块/按内外网分类的调用次数」 | **是** |
| 表格 | **TDesign Table** | 调用明细表、按域名聚合表，沿用现有组件库 | 否 |
| 全屏编辑 | **Monaco** (已装) | 请求头/体格式化 + 新增全屏放大 | 否 |
| 全局状态 | **pinia 2.3.1** | 链路/变量/调试上下文跨组件共享 | **是** |

### 2.1 为什么是 X6 而不是 LogicFlow（2026-08-04 复核后改选）

初版设计选 LogicFlow，理由是「依赖已装、零成本」。复核发现**该理由不成立**，故改选 X6：

- 项目实装的是 `@logicflow/core@1.2.28`，**落后主线两个大版本**（LogicFlow 现为 2.2.x）。1.2 不支持 Vue 组件节点，只能用 `h()` 手写 SVG；要做富节点必须升 2.x，属破坏性升级 → 「零成本」是伪优势。
- 本项目是**属性面板驱动的节点重绘闭环**（改 URL/方法/内外网 → 节点须立刻重绘）。LogicFlow 的 Vue 节点走 Teleport，此路径有已知缺陷：issue #2128（`setProperties` 后节点不重绘）、#2206（Vue 节点拖拽后不释放），以及 Vite 下 `vue-node-registry` 需配 alias 才能解析。X6 的 `x6-vue-shape` 在该路径上成熟稳定。
- HTTP 节点内容重（方法徽标 + URL 摘要 + 内外网标签 + 调试状态色 + 等待时间），X6 里就是一个普通 Vue SFC，直接用 TDesign；LogicFlow 需手搓 SVG。
- 砍掉 `sort_no`/`parallel_group` 后执行顺序由拓扑决定，本质是 **DAG**。X6 官方定位即 DAG 引擎，配 `@antv/algorithm` 可做拓扑排序与环检测；LogicFlow 无图算法。
- 关系图用 G6 与编排用 X6 **同属 AntV、底层同源（AntV G 渲染引擎）**，样式体系与心智模型统一。
- 客观记录：两者均活跃维护（LogicFlow 最近提交 2026-07-30，X6 2026-07-31），此选择是「更合适」而非「对错」。LogicFlow 在 OA 审批流场景仍是更优解。

> ⚠️ **依赖版本陷阱（务必遵守）**：`@antv/x6-plugin-*` 各包在 npm 上的 `latest` tag 仍指向 2.x（如 selection 的 latest 是 2.2.2），但 2.x 的 peer 为 `@antv/x6: ^2.x`，与核心 3.1.7 不兼容。**必须在 package.json 中锁定精确版本 `"3.0.0"`**（3.0.0 的 peer 才是 `^3.x`），不可写 `^` 或 `latest`。

> 关于「系统调用关系图」为何不用 X6：X6 是**可编辑图**引擎（用户手绘拖拽），而调用关系图是**由数据自动布局的关系网络**，需要力导/dagre 等布局算法。G6 才是自动布局与图分析场景的正解。两者分工：X6 管人画的图，G6 管数据生成的图。

## 3. 前端架构

### 3.1 链路编排页重构（核心）
- **拆分** `ChainEdit.vue`(2224 行) → 目录 `frontend/src/views/chain/`：
  - `ChainEditor.vue`（容器：X6 画布 + 右侧面板 + 工具栏）
  - `components/x6/HttpNode.vue`（X6 自定义 HTTP 节点，**Vue SFC + TDesign**：方法徽标 + URL 摘要 + 内外网标签 + 调试状态色 + 等待时间）
  - `components/x6/graph.js`（X6 Graph 初始化、插件注册、节点/边注册、拓扑排序与环检测）
  - `components/panels/BasicPanel.vue`（节点名称；**去掉排序号、去掉并行分组；保留等待时间**）
  - `components/panels/RequestPanel.vue`（方法/URL/请求头/请求体；**请求体类型扩到 5 种；请求体加格式化+全屏放大**）
  - `components/panels/AssertPanel.vue`（断言规则重设计）
  - `components/panels/ExtractPanel.vue`（提取规则 + 试提取）
  - `components/panels/VariableBindPanel.vue`（变量绑定：从上游响应选字段喂入参）
  - `components/DebugDrawer.vue`（单节点调试：运行→展示响应→点字段插入变量）
  - `components/GlobalVarPanel.vue`（全局变量管理面板）
- **画布交互**：左侧不再有「节点库」，改为顶部工具栏「+ HTTP 节点」按钮直接落节点；节点间拖锚点连线即建立依赖；顺序由图拓扑决定（不再有排序号）。
- 删除：节点库面板、节点列表面板、版本历史面板、版本选择「0」框、列表/分组视图切换、批量导入对话框及全部逻辑、HTTP请求/发送HTTP请求字样。

### 3.2 单节点调试 + 变量绑定（需求 9-12 条）
- 选中节点 → 点「调试运行」→ 调 `POST /api/node/debug` → `DebugDrawer` 展示状态码/响应体/耗时。
- 响应体字段可点击 → 弹出「绑定到：下一节点 URL / 请求头 / 请求体 / 提取为变量」→ 自动在上游节点生成提取规则、在当前节点入参写入 `${varName}`。
- 支持基于状态码/字段存在性/字段值 配置条件分支（边条件，可选 v1 简化：仅顺序）。

### 3.3 全局变量
- `variableStore`(pinia) + `GlobalVarPanel`：系统级 + 链路级变量（name/value/类型/是否加密）。
- 节点 URL/头/体均支持 `${varName}` 占位符，执行引擎统一替换。

### 3.4 请求体类型扩展（需求 6-7 条）
扩展到 **5 种**（对齐行业标准）：
1. `json` (application/json)
2. `form-data` (multipart/form-data，含文件)
3. `x-www-form-urlencoded`
4. `raw` (text/xml / application/xml / text/plain，下拉子类型)
5. `binary` (文件二进制)
- 请求头已有格式化；**请求体补格式化 + Monaco 全屏放大**（新增 `fullscreen` 按钮与弹层）。

### 3.5 断言/提取规则重设计（需求 8 条）
- **断言** `{ "rules": [ { "target":"STATUS|body.path", "operator":"eq|ne|contains|gt|lt|gte|lte|regex|notNull|exists", "expected":"" } ] }`
  - 覆盖率：状态码检查 + 响应体字段检查；operator 全部落库、全部被后端识别。
  - 提供「从响应自动生成断言」辅助。
- **提取** `{ "rules": [ { "varName":"token", "source":"jsonPath|regex", "expr":"$.data.token" } ] }`
  - 提供「试提取」：贴一段样本响应，预览提取结果。

### 3.6 系统调用关系图（需求 23-25 条，新菜单）
- 新路由 `/system/call-graph` → `CallGraph.vue`：
  - **图(G6)**：节点=系统/模块，边=调用关系，按 INTERNAL/EXTERNAL 着色，边宽=调用次数；支持力导/ dagre 切换。
  - **统计(ECharts)**：按模块调用次数饼图、内外网占比柱状图。
  - **表(TDesign)**：① 调用明细（链路/来源模块/目标系统/方法/URL/内外/次数）② 按域名/IP 聚合（域名/内外/模块/命中数）。
  - 依赖「系统注册表」(`sys_system_registry`) 中配置的内部/外部域名或 IP → 解析出每个节点的目标系统。

## 4. 后端架构（Java 8）

### 4.1 新增/改造接口
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/node/debug` | 单节点调试执行，返回响应(状态/头/体/耗时)，不写执行日志 |
| GET/POST | `/api/variable/list` `/api/variable/save` `/api/variable/delete` | 全局/链路变量 CRUD |
| GET/POST/DELETE | `/api/system-registry/list` `/save` `/delete` | 系统注册（域名/IP→模块/内外）CRUD |
| GET | `/api/call-graph/data` | 返回关系图数据（nodes/edges + 统计 + 明细表） |
| GET | `/api/call-graph/by-module` `/by-domain` | 按模块/按域名聚合 |
| （改造）| `/api/chain/save` `/api/node/save` | 接收 X6 图数据(graphData) 替代 sortNo 列表 |

### 4.2 内外网识别 `InterfaceClassifier`
- 输入 URL → 取 host → 匹配 `sys_system_registry`（域名模式 / IP 段）→ 返回 `{scope: INTERNAL|EXTERNAL|UNKNOWN, systemCode, systemName}`。
- 节点保存时落 `interface_scope` + `target_system`；编排页/列表展示内外标识。

### 4.3 执行引擎改造 `ExecuteServiceImpl`（Java 8）
- 拓扑排序执行 X6 图；`${varName}` 统一替换（全局+链路+上游提取）。
- **断言**支持全部 operator；异常不再静默通过，4xx/5xx 预期场景可判通过。
- **提取**支持 jsonPath + regex；执行日志回填 `extracted_vars`（修复现有永 NULL 缺陷）。

### 4.4 删除的冗余（后端）
- `NodeConfigController.importNodes` + `/api/node/import` 接口 + `NodeImportDTO`(死代码)。
- （保留）版本表与回放接口——插件回放依赖，仅前端隐藏版本 UI。

## 5. 数据模型（表结构重构）

### 5.1 `test_node_config` 变更
- **删除**：`sort_no`（UNIQUE 约束导致重排冲突，改为图拓扑）、`parallel_group`（需求明确去掉）。
- **保留**：`delay_seconds`（等待时间必须保留）、`extract_rules`、`assert_rules`、`variable_mapping`（启用）。
- **新增**：
  - `interface_scope` varchar(16)  — INTERNAL/EXTERNAL/UNKNOWN
  - `target_system`  varchar(64)  — 解析出的目标系统编码
  - `graph_data`     longtext     — 该节点在 X6 画布中的坐标/连线元数据（可选，整体图可存 chain 级）
  - `body_type` 值域扩展为上述 5 种
- 链路级图数据存 `test_chain.graph_data`（longtext，X6 `graph.toJSON()` 全量 JSON）。

### 5.2 新增 `test_global_variable`
```
id bigint PK, var_scope varchar(16) (GLOBAL/CHAIN), chain_code varchar(64),
var_name varchar(64), var_value longtext, var_type varchar(16),
is_encrypted tinyint default 0, description varchar(255),
create_time, update_time
```

### 5.3 新增 `sys_system_registry`（设置页：内部/外部域名或 IP）
```
id bigint PK, system_code varchar(64) UNIQUE, system_name varchar(128),
scope varchar(16) (INTERNAL/EXTERNAL),
domain_patterns longtext (JSON 数组, 如 ["*.pay.com","api.inner"]),
ip_ranges longtext (JSON 数组, 如 ["10.0.0.0/8","192.168.1.5"]),
category varchar(64), description varchar(255), create_time, update_time
```

### 5.4 `init.sql` 统一
- 以 `docker/init.sql` 为权威；`backend/docker/init.sql` 废弃合并；补上述新增表/字段；保持两份（外层 + backend）一致。

## 8. 风险与验证

| 风险 | 缓解 |
|---|---|
| X6 插件 npm latest tag 指向 2.x，与核心 3.x 不兼容 | package.json 中把 `@antv/x6-plugin-*` **锁死为精确版本 `3.0.0`**，禁止用 `^` 或 latest；核心用 `@antv/x6@^3.1.7` |
| X6 3.0 移除 namespace，网上 2.x 教程会失效 | 以 3.x 官网与 `node_modules/@antv/x6/dist` 类型定义为准，不照抄旧博客 |
| `x6-vue-shape` 依赖 vue-demi，peer 含 `@vue/composition-api` | Vue 3 下该 peer 不需要，安装用 `--legacy-peer-deps`（本项目 TDesign 已有此惯例） |
| 图数据→执行顺序 | 拓扑排序；出现环则提示用户，不执行 |
| 版本表保留导致旧字段冗余 | 仅隐藏 UI，不动表，回放链路不受影响 |
| G6/ECharts 包体增大 | 按需引入，仅关系图页加载 |
| 断言旧数据兼容 | 迁移脚本把旧 `{statusCode,body}` 转新 `rules[]` 结构 |

**验收门槛**：后端 `mvn clean package` 通过；前端 `npm run build` 通过（不只 dev）；本地启动链路编排可拖拽连线保存、单节点调试出结果、全局变量生效、调用关系图有数据。
