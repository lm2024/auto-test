## 一、需求确认记录

### 1.1 问题确认结果

| # | 问题 | 确认结果 |
|---|------|---------|
| 1 | 回放时 Cookie/登录态 | 使用浏览器当前 Cookie，不单独管理 |
| 2 | 环境变量替换 | V1 不支持 |
| 3 | 相同链路定义 | URL 路径（忽略 GET 参数）+ Method |
| 4 | Diff 对比粒度 | JSON 字段级 Diff |
| 5 | 版本保留策略 | 保留所有版本，前端默认展示前 5 条，支持手动清理 |
| 6 | 回放失败处理 | 默认继续，标记失败，结束后汇总 |
| 7 | 推送策略 | 自动创建新版本，保留历史 |
| 8 | 版本创建策略 | 自动创建 + 手动创建，可在设置中配置 |
| 9 | GET 参数处理 | 部分忽略（用于指纹计算时忽略，请求本身保留） |
| 10 | 脱敏策略 | 不脱敏 |
| 11 | 并行回放 | 支持并行组 |
| 12 | 变量传递 | **不需要**。回放目的是收集新参数，不是传递历史变量 |
| 13 | AI 集成 | 增加 AI 分析差异影响 |
| 14 | 权限控制 | 暂不区分 |

### 1.2 核心理解（关键）

**回放的本质：不是简单重发 HTTP 请求，而是通过浏览器交互来收集新的接口参数。**

```
回放的目的：
  ❌ 不是：按历史数据原样重发请求
  ✅ 而是：在浏览器中重新走一遍业务流程，捕获新的请求/响应数据

回放的过程：
  1. 插件打开链路的起始页面
  2. 用户在页面上进行操作（点击按钮、填写表单、导航）
  3. 插件在后台持续捕获所有网络请求（CDP + fetch/XHR 拦截）
  4. 用户操作完成后，插件展示捕获到的新请求列表
  5. 用户选择需要更新的请求，推送至平台
  6. 平台对比新旧链路，标注差异
```

## 二、回放模式设计

### 2.1 两种回放模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **HTTP 回放** | 按链路顺序直接发送 HTTP 请求，收集响应 | 接口参数不变，仅验证响应变化 |
| **浏览器回放** | 打开页面，用户交互，插件捕获新请求 | 接口参数可能变化，需要通过页面交互获取新参数 |

### 2.2 HTTP 回放流程

```
┌─────────────────────────────────────────────────┐
│  1. 插件展示链路接口列表                          │
│  2. 用户点击「HTTP 回放」                         │
│  3. 插件按顺序 fetch 每个接口                     │
│     ├── 使用浏览器当前 Cookie                     │
│     ├── 支持并行组（同组接口并发执行）              │
│     ├── 记录每个接口的响应                        │
│     └── 失败的接口标记但继续执行                   │
│  4. 回放完成 → 展示结果汇总                       │
│  5. 用户选择接口 → 推送至平台                     │
└─────────────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────────────┐
```

#### A2. 回放引擎

```javascript
// replay.js - 双模式回放引擎
class ChainReplayer {
  constructor(chain, options = {}) {
    this.chain = chain;
    this.nodes = chain.nodes;
    this.mode = options.mode || 'http'; // 'http' | 'browser'
    this.results = [];
    this.isPaused = false;
    this.isStopped = false;
    this.capturedApis = []; // 浏览器模式下捕获的新请求
  }

  // HTTP 回放：直接发送请求
  async httpReplay() {
    for (const node of this.nodes) {
      if (this.isStopped) break;
      while (this.isPaused) await sleep(100);
      
      const result = await this.executeHttpRequest(node);
      this.results.push(result);
      this.onLog(result);
    }
    return this.results;
  }

  // 浏览器回放：打开页面 + 激活捕获
  async browserReplay() {
    // 1. 打开第一个接口的 URL
    const startUrl = this.extractBaseUrl(this.nodes[0].requestUrl);
    await chrome.tabs.create({ url: startUrl });
    
    // 2. 激活网络捕获（CDP + fetch/XHR 拦截）
    await this.startCapture();
    
    // 3. 等待用户操作（用户点击「完成回放」后继续）
    await this.waitForUserAction();
    
    // 4. 停止捕获，收集结果
    await this.stopCapture();
    
    return this.capturedApis;
  }

  // 从捕获的请求中匹配链路接口
  matchCapturedToChain(captured, chain) {
    return captured.map(req => {
      const matched = chain.nodes.find(n => 
        n.requestMethod === req.method &&
        this.normalizeUrl(n.requestUrl) === this.normalizeUrl(req.url)
      );
      return {
        ...req,
        matchedNode: matched || null,
        isNew: !matched, // 未匹配到 = 新增接口
        isModified: matched ? this.detectChanges(matched, req) : false
      };
    });
  }

  // URL 标准化（忽略 GET 参数）
  normalizeUrl(url) {
    const q = url.indexOf('?');
    return q > 0 ? url.substring(0, q) : url;
  }
}
```

#### B2. 链路指纹算法

```java
public String generateFingerprint(List<PluginInterfaceDTO> nodes) {
    // 1. 按 sort 排序
    nodes.sort(Comparator.comparingInt(PluginInterfaceDTO::getSort));
    
    // 2. 提取 method + URL路径（忽略GET查询参数）
    String raw = nodes.stream()
        .map(node -> {
            String method = node.getMethod().toUpperCase();
            String urlPath = extractUrlPath(node.getUrl()); // 去掉 ? 后的部分
            return method + "|" + urlPath;
        })
        .collect(Collectors.joining("|"));
    
    // 3. MD5
    return DigestUtils.md5Hex(raw);
}
```

#### B3. Diff 计算

```java
public DiffResult computeDiff(List<NodeSnapshot> current, List<NodeSnapshot> previous) {
    DiffResult result = new DiffResult();
    
    Map<String, NodeSnapshot> prevMap = previous.stream()
        .collect(Collectors.toMap(NodeSnapshot::getNodeName, Function.identity()));
    Map<String, NodeSnapshot> currMap = current.stream()
        .collect(Collectors.toMap(NodeSnapshot::getNodeName, Function.identity()));
    
    // 检测修改和删除
    for (NodeSnapshot prev : previous) {
        NodeSnapshot curr = currMap.get(prev.getNodeName());
        if (curr == null) {
            result.addRemoved(prev);
        } else {
            List<FieldChange> changes = compareFields(prev, curr);
            if (!changes.isEmpty()) {
                result.addModified(curr, changes);
            } else {
                result.addUnchanged(curr);
            }
        }
    }
    
    // 检测新增
    for (NodeSnapshot curr : current) {
        if (!prevMap.containsKey(curr.getNodeName())) {
            result.addAdded(curr);
        }
    }
    
    return result;
}

private List<FieldChange> compareFields(NodeSnapshot prev, NodeSnapshot curr) {
    List<FieldChange> changes = new ArrayList<>();
    checkField(changes, "requestUrl", "请求地址", prev.getRequestUrl(), curr.getRequestUrl());
    checkField(changes, "requestMethod", "请求方法", prev.getRequestMethod(), curr.getRequestMethod());
    checkField(changes, "requestHeaders", "请求头", prev.getRequestHeaders(), curr.getRequestHeaders());
    checkField(changes, "bodyData", "请求体", prev.getBodyData(), curr.getBodyData());
    checkField(changes, "responseCode", "响应码", prev.getResponseCode(), curr.getResponseCode());
    checkField(changes, "responseBody", "响应体", prev.getResponseBody(), curr.getResponseBody());
    return changes;
}
```

## 五、版本管理策略

### 5.1 版本创建

| 场景 | 行为 |
|------|------|
| 插件 HTTP 回放后推送 | 自动创建新版本（设置可配置为手动） |
| 插件浏览器回放后推送 | 自动创建新版本 |
| 前端手动编辑保存 | 创建新版本 |
| 插件直接推送（不回放） | 创建新版本（现有功能） |

### 5.2 版本查询

- 默认展示最近 5 个版本
- 支持加载全部版本
- 超过 30 个版本时提示可清理

### 5.3 版本清理

- 手动删除单个版本
- 批量删除指定时间之前的版本
- 删除需二次确认

## 八、验收标准

| # | 验收项 | 通过标准 |

| 7 | Diff 对比 | 新旧版本接口差异被正确识别 |

| 9 | 变更摘要 | 页面顶部正确显示新增/删除/修改/未变数量 |
| 10 | 版本管理 | 同一链路可保存多个版本，支持查看/删除历史版本 |
