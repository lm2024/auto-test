## 一、时代背景：AI 不是噱头，要找到对的场景

### 1.1 宏观趋势

- 国家大力推进「人工智能 +」各行业深度融合
- 测试工作不应停留在「人海战术」
- 关键问题：AI 用在哪？怎么用？能不能落地？

### 1.2 我们的回答

**精准 AI，不做花架子。**

- 只做 2 个高价值 AI 能力
- 均基于已有链路模板，无模板不凭空生成
- AI 未配置时自动降级，基本能力不受影响

## 三、AI 能力深度解读

### 3.1 AI 能力一：全链路智能造数

**解决什么问题：** 测试数据构造依赖人工编写，ID 递增、业务合规数据生成成本高。

**怎么工作：**

```
输入：数据库中已有的链路节点模板
  （URL、字段结构、业务含义）
    ↓
处理：内网大模型按业务规则生成合规数据
    ↓
输出：按节点返回请求头、请求体
    ↓
确认：人工确认后保存（不强制自动落库）
```

**ID 策略：**
- 自增模式：基于历史最大 ID 按步长递增
- 自定义模式：手动指定起始值

### 3.2 AI 能力二：失败智能诊断

**解决什么问题：** 接口执行失败后，人工比对请求响应、定位根因，平均 30-60 分钟。

**怎么工作：**

```
输入：完整请求 + 响应状态码 + 响应体 + 错误堆栈
    ↓
分析：参数错误 / 字段缺失 / 权限不足 / 业务校验失败 / 服务异常
    ↓
输出：
  - 根因定位
  - 排查步骤
  - 修复方案
```

**降级策略：** 大模型不可用时，按 HTTP 状态码返回规则分析模板。

### 3.3 AI 安全边界

| 原则 | 具体措施 |
|------|----------|
| 数据不出网 | 所有 AI 调用走内网大模型服务 |
| 不凭空生成 | AI 只基于已有模板工作 |
| 人机协同 | 生成结果需人工确认后才落库 |
| 可追溯 | 完整日志留痕 |

## 四、为什么 AI 回归比 AI 新功能测试更靠谱

| 维度 | 回归场景 | 新功能场景 |
|------|----------|------------|
| 业务路径 | 固定、已验证 | 未定、频繁变化 |
| 接口结构 | 稳定 | 频繁变动 |
| AI 模板 | 可长期复用 | 维护成本高 |
| 投入产出 | 高 | 低 |
| **结论** | **AI 最佳战场** | 建议仍以人工为主 |

### 场景定位

- **核心定位**：既有功能的回归验证与稳态保障
- **能降低**：大量重复的手工接口回归
- **不适合**：全新业务首次验证、频繁变更接口

## 六、AI 与自动化的协同关系

```
自动化 → 解决「重复执行」→ 机器干机器的活
AI     → 解决「数据构造」和「故障诊断」→ 智能干智能的活
人工   → 解决「业务判断」和「最终决策」→ 人干人的活
```

**三者协同，而非互相替代 —— 这才是 AI 时代的正确打开方式。**

## 十、问答备答（AI 相关精选）

**Q：AI 是不是噱头？**

A：我们只做两个场景：智能造数和失败诊断。均基于已有模板，有规则降级。不是花架子。

**Q：AI 会不会编造数据？**

A：不会。AI 只读取数据库中已有的链路模板，按字段结构生成合规数据。生成后需人工确认才落库。

**Q：数据会不会泄露到外部？**

A：不会。所有 AI 调用走内网大模型服务，数据不出网。

**Q：AI 和自动化是什么关系？**

A：自动化解决重复执行，AI 解决数据构造和故障诊断，人工做业务判断。三者协同。

**Q：未来 AI 还能做什么？**

A：变更影响分析、智能用例推荐、自然语言建用例、质量态势大屏等，随内网大模型能力增强逐步落地。
